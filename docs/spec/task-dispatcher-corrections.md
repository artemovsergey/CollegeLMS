# ТЗ: Диспетчер — Корректировки расписания (пакетная модель)

> **Формулировка по факту реализации.** Изначально задача задумывалась для
> мини-приложения в боте Max, по итогам основная реализация выполнена на вебе
> (раздел **Диспетчер → Корректировки**). Дублирующая ручная форма доступна в
> мини-приложении Max (`max/DispatcherManual`), уведомления — через бота Max.

## 1. Цель

Дать диспетчеру инструмент подготовки и применения корректировок расписания:
ручное создание позиций (добавление/замена/снятие/перенос), импорт готового
XLSX, редактирование, применение с обязательным подтверждением и уведомлением
затронутых групп и преподавателей в мессенджере Max.

## 2. Область и роли

- Раздел **Диспетчер → Корректировки** (веб): вкладки **Пакеты / Редактор / Импорт**.
  Журнала здесь нет — просмотр изменений живёт на отдельной странице **Изменения**
  (`/changes`), там же откат отдельной записи.
- Роли: `Dispatcher`, `Admin`.
- Смежные модули: `ScheduleService` (расписание, применение), MaxBot (уведомления), хранилище файлов (XLSX).

## 3. Модель данных

| Сущность | Назначение | Ключевые поля |
|---|---|---|
| `CorrectionBatch` | Пакет корректировки на дату | дата, неделя, день недели, статус, создатель, применивший, `AppliedAt`, список позиций |
| `CorrectionPosition` | Одна позиция пакета | тип (`Add`/`Remove`), группа, день, неделя, № пары, предметы/преподаватели (текущий и снимаемый), примечание, статус, `HistoryId` |

Форма и импорт XLSX создают только два типа: `Add` и `Remove`. Замена и перенос —
это `Add` с заполненными полями `Removed*`:

| Поля позиции | Что получится |
|-------------|--------------|
| `Removed*` пусты | новое занятие в выбранной паре (слот свободен или занятость не важна) |
| `Removed*` = прежнее занятие этой пары | **замена**: прежнее снимается, новое встаёт на его место |
| `RemovedNumberPair` = X (и `Removed*` = вводимое занятие) | **перенос** `вм.X`: пара X освобождается |
| оба случая | замена с переносом: снимается прежнее в паре Y и вводимое в паре X |

Значения `Replace` и `Move` остались в перечислении: в базе есть пакеты и записи
журнала, созданные до объединения операций. Их понимает и движок, и откат, а
запросы `POST`/`PUT` позиций с такими типами приводятся к `Add`.

Статусы пакета: `Draft` (отображается как **«Подготовлен»**) → `Applied` (**«Применён»**).
Статуса «Отменён» не существует: применённый пакет **удаляется** целиком — расписание
откатывается к состоянию до корректировки, записи журнала удаляются. Черновой пакет
удаляется без отката, потому что расписание он ещё не менял.

## 4. Функциональные требования

### 4.1. Ручное создание корректировки

**Операций всего две: «Добавить» и «Снять».** Всё остальное — решение внутри
добавления: что делать с занятием в выбранной паре («в параллель» или «заменить»)
и служебные отметки примечания. Меньше типов — меньше ошибок при выборе.

1. Начало работы — модальное окно с выбором **даты корректировки**.
2. По дате автоматически определяются **номер недели** и **день недели**.
3. Дату подготовленного пакета можно **изменить**: неделя, день и позиции
   пересчитываются. Для применённого пакета дата неизменна (`409`).
4. В шапке формы указана **дата корректировки** — она в модальном окне, а не на
   странице.
5. Кнопка **«Добавить позицию»** неактивна, пока не заполнены все обязательные
   шаги; причина видна подписью слева от кнопок. Когда позиция готова, вместо
   причины показывается итог одной фразой («Пара 4: добавить «Математика» ·
   вместо «Физика» · пара 2 освободится»).
5.1. **Предпросмотр строки** — над кнопками всегда показана строка позиции в том
   виде, в каком она уйдёт в файл корректировки и в уведомление бота: группа,
   «Снимается», «Вводится», № пары, примечание. Правила те же, что у выгрузки
   XLSX (перенос пишется только примечанием «вм.X»), поэтому предпросмотр не
   расходится с файлом.

Порядок шагов: `Операция → Группа → Пара → …` — пара всегда выбирается в
карточке дня, иначе смена операции меняла бы саму форму.

**Слоты — семь.** В учебном дне семь пар, поэтому в карточке дня показываются
слоты 1–7; номер вне диапазона даёт ошибку «1–7».

**Добавить** — `Операция → Группа → Пара → Преподаватель → Предмет → (занятая пара) → Примечание`

- После выбора группы показывается **полная карточка расписания группы на день** —
  все пары 1–7, и занятые, и свободные; слот выбирается по ней.
- Преподаватель выбирается только из ведущих у группы, предмет — только из
  предметов этого преподавателя в этой группе.
- Занятый слот **не блокируется**: появляется шаг **«Что делаем с занятием в
  паре»** — «поставить в параллель» (прежнее остаётся) или «заменить» (прежнее
  снимается, новое встаёт на его место). Шаг показывается только когда слот
  занят, поэтому номера шагов считаются под него.
- При замене в шаге выбирается конкретное занятие из слота; если в слоте оно
  одно, выбирать нечего. Занятие, которое уже трогает другая позиция пакета,
  выбрать нельзя.
- **Занятость слота не зависит от выбранного занятия**: шаг остаётся на месте
  после выбора, иначе диспетчер теряет вид, что именно он заменяет.
- Замена занятия **на то же самое** запрещена: пара была бы удалена и создана
  заново вместе с аудиторией и другими неделями. Форма сообщает «Нельзя заменить
  занятие на такое же», движок отклоняет такую позицию строкой ошибки.

**Снять** — `Операция → Группа → Пара → Занятие в паре → Примечание`

- Занятие выбирается прямо в карточке дня: клик по занятию выбирает и пару, и
  занятие сразу.
- Разница только в примечании: пустое — обычное снятие, служебное слово
  `снять` — метка позиции снятия (на расписание не влияет).

### 4.2. Служебные слова примечания

Логику задают **три** слова, остальной текст — информация для преподавателей и
студентов:

| Слово | Что делает |
|-------|-----------|
| `сам.р` | самостоятельная работа **только для информирования**: сама пара в расписание **не встаёт** (в базе нет), но показывается в расписании как пометка с бейджем «Сам.р.»; слот не занимается |
| `сам.р+` | та же самостоятельная работа, но пара **добавляется в расписание** и помечается |
| `вм.X` | пара «откуда»: занятие преподавателя с предметом замены переносится из пары X в выбранную |
| `снять` | метка позиции снятия: в файле и в уведомлении видно, что пара именно снимается. На расписание не влияет |

В форме самостоятельная работа настраивается **двумя тумблерами**: первый
«Это самостоятельная работа?», второй (появляется только после первого) — «Ввести
пару в расписание?». Оба выключены — обычная пара; первый включён, второй
выключен — `сам.р`; оба включены — `сам.р+`. Слова ставится переключателями, руками
набирать не нужно; если они встретились в свободном тексте, форма распознаёт их
при потере фокуса и переносит в переключатели. Само примечание всегда видно
собранным — в том виде, в каком его поймёт система.

**Информационная пара (`сам.р`) видна в расписании** дня и недели: она
собирается из журнала (`GET /api/schedule`), помечается бейджем «Сам.р.» и
показывается студентам и преподавателю. В базе расписания такой пары нет, поэтому
снять её нельзя — снять можно только настоящее занятие. В карточке дня группы
корректировки такая пара видна как «только информация», в журнале изменений — как
«Добавлено» с пометкой «Только информация», в уведомлении бота — как
«🟣 Сам.р. (только информация)».

**Отметки сочетаются между собой.** `сам.р` не мешает замене и `вм.X`: они
относятся к физическим изменениям, а она — к тому, встанет ли сама пара. Так
работают реальные случаи «пара отменяется, студенты занимаются сами» (снять
занятие + `сам.р`) и «перенесли и отметили самостоятельную работу»
(`вм.X` + `сам.р`): снятия выполняются по-настоящему, а пара остаётся только
пометкой.

### 4.2.1. Правило занятости слота

**Пара — это время, а не предмет.** В одной паре может быть несколько занятий:
преподаватель ведёт две группы подряд, ин.язык делится между двумя
преподавателями, в пару добавили второе занятие.

Отсюда правило: **пару можно поставить в занятый слот.** Это не ошибка,
блокировки нет ни во фронтенде, ни в движке применения. Снимает занятие только
явный выбор «заменить» (или снятие).

- «Добавить» кладёт второе занятие в слот, `Removed*` пустые.
- «Заменить» снимает прежнее занятие и ставит новое на его место.
- Пометки `сам.р` в слоте не стоят: пара, которой нет в расписании, не мешает
  ни добавить, ни заменить.

### 4.2.2. Соглашение `вм.X` (перенос)

`вм.X` — это **пара «откуда»**, а не «вместо». X выбирает диспетчер из списка
пар; автоподстановки нет, потому что номер пары назначения указывается отдельно
и в реальных файлах они не совпадают.

Перенос возможен, только если **в паре X у этого преподавателя стоит этот же
предмет** в этой группе в этот день. Форма предлагает только такие пары: если
подходящих нет, перенос недоступен. Движок проверяет то же самое и в случае
расхождения пишет ошибку позиции: «в паре X нет занятия «Предмет Преподаватель» —
перенос невозможен». Иначе перенос унёс бы чужое занятие.

Без `вм.X` вводимое занятие просто появляется в паре Y, а в паре, откуда оно
пришло, остаётся — то есть продублируется.

| Позиция | Что делает движок |
|---------|------------------|
| Добавление + `вм.X` | освобождает пару X, вводит занятие в выбранную; одна запись журнала «добавлено» |
| Замена + `вм.X` | освобождает пару X, в выбранной паре заменяет занятие; **две** записи журнала — «добавлено» и «снято» |

Значение `вм.X` пишется в ту же колонку «Примеч.» файла корректировки, поэтому
импорт и экспорт XLSX остаются обратимыми, а реальные файлы за 4 недели читаются
без изменений.

### 4.3. Импорт файла XLSX

1. Диспетчер загружает файл `.xlsx` (до 10 МБ).
2. Файл проходит **валидацию данных**; при ошибках показывается подробный список: `Строка N, стлб. M: сообщение`.
3. Соглашения импорта:
   - строка с заполненными только колонками «Снимается по расписанию» становится позицией `Remove`;
   - строка с колонками «Вводится в расписание» становится позицией `Add`; если колонка «Снимается» тоже заполнена, это **замена** (занимаемое поле `Removed*`), если в примечании `вм.X` — **перенос** из пары X;
   - `сам.р` в примечании действует по соглашению 4.2: пара не встаёт, остаётся пометка; `сам.р+` — встаёт.
4. При успешной валидации создаётся **пакет** (`batchId` в ответе) со списком всех позиций.
5. Каждую позицию можно **просматривать, редактировать, удалять, добавлять**. Хранение — отдельная сущность в БД (`CorrectionBatch`/`CorrectionPosition`).
6. Скачивание XLSX с **актуальными данными после редактирования**; имя файла — `Корректировка_ddMM.xlsx`, где `ddMM` — **день и месяц даты корректировки** из шапки файла (без года; год виден в самом файле). Для позиций переноса примечание выводится как «вм.X».
7. Преподаватель в файле пишется **с инициалами**: «Иванов Иван Иванович» → «Иванов И.И.»; уже сокращённое «Абатуров С.А.» и перечисление через слеш не меняются.

**Строки одного файла видят изменения предыдущих строк.** Файл описывает изменения на одну дату и строки идут по порядку: если строка вводит занятие, следующая может снять или заменить именно его. Пока пакет не применён, в `schedule_entries` этого занятия нет, поэтому разбор ведёт виртуальное расписание (`CorrectionOverlay`): в начале разбора на группу/день/неделю состояние подтягивается из БД один раз, дальше меняется по мере разбора строк. Снятое занятие последующим строкам уже не видно; наложение ведётся по группе, поэтому чужое занятие по имени группы не находится. Тот же приём использует движок применения (`CorrectionApplyEngine`), поэтому разбор и проверка пакета видят одинаковую картину.

### 4.4. Применение корректировки

1. Когда пакет готов — кнопка **«Применить»**.
2. Обязательно **подтверждение** выбора (диалог).
3. Применение **транзакционное**: при ошибке — `400`, частичных изменений нет.
4. Повторный apply — `409` (пакет уже применён). Идемпотентность — заголовок `Idempotency-Key`.
5. После успеха: пакет → **«Применён»**, позиции → «Применён» + ссылка на запись журнала; данные расписания обновлены в БД.
6. После применения **автоматически скачивается XLSX**.
6.1. **Предпросмотр пакета в виде файла** (экспериментально): кнопка «Предпросмотр» в
   редакторе повторяет шаблон 1:1 — три строки заголовка, двухстрочная шапка
   (Группа / Снимается по расписанию / Вводится в расписание / № / Примеч.),
   Times New Roman, рамка и те же примечания, что уйдут в файл. Нужен, чтобы
   проверять пакет без скачивания.
7. **Уведомления в мессенджере Max**: все группы и преподаватели из корректировки получают уведомление, если они **выбраны текущими** (подписаны). Уведомление содержит **дату и все позиции** корректировки, относящиеся к получателю (агрегированное, одно сообщение на получателя). Преподаватель матчится по текущему **или снятому** (`RemovedTeacherName`) — снятый преподаватель также получает уведомление. Исходов в уведомлении два: 🟢 добавлено и 🔴 снято; для самостоятельной работы добавляется пометка «🟣 сам.р.» либо «🟣 сам.р. (только информация)», если пара не вставала.
8. **Настройка уведомлений** — при старте бота через меню кнопок. По умолчанию время уведомлений — **7:30 утра**.
9. **PNG-картинка в канал Max**: после применения API рендерит таблицу корректировки (QuestPDF, `RasterDpi = 144`) и отправляет её в бот, который публикует изображение в канал `MaxBot:CorrectionChannelId`. Пустой канал → warning и пропуск. Сбой уведомлений/картинки не откатывает применение (fail-safe).

### 4.5. Удаление пакетов

- Удаление **подготовленного** пакета — просто удаляет его и его позиции.
- Удаление **применённого** пакета — сначала откатывает его записи журнала
  (расписание возвращается к состоянию до корректировки), затем удаляет пакет.
- Кнопка **«Очистить применённые»** удаляет все применённые пакеты разом —
  удобно в начале нового семестра. Черновые пакеты не трогаются.
- Записи журнала привязаны к пакету (`schedule_history.batch_id`) — без этой связи
  нельзя было бы откатить пакет целиком.

### 4.6. Журнал корректировок (страница «Изменения»)

- Отдельная страница **«Изменения»** показывает историю применённых изменений с фильтрами по неделе (`week`), конкретной дате (`date`), периоду применения (`from`/`to`), типу изменения (`changeType`), группе и преподавателю (`groupId`/`teacherId`, включая снятого), с пагинацией.
- В карточках изменений всего два исхода: **«Добавлено»** и **«Снято»**. Замена показывается как «старое => новое», перенос — как «пара X → Y»; `сам.р+` помечается как самостоятельная работа, `сам.р` — как «только информация» с пояснением, что пара в расписание не вставала.
- Бейджи на парах расписания тоже только двух видов: «Добавлено» и «Снято» (подробности — в подсказке бейджа).

## 5. API (REST)

Роли: `Dispatcher`, `Admin`; `GET /api/schedule/history` — `AllowAnonymous`.

### 5.1. Канонический batch-флоу (веб)

Базовый путь: `/api/schedule/correction/batches`.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/` | Создать пакет по дате (`400` — нет даты / выходной / вне семестра) |
| GET | `/?status=&from=&to=&page=&pageSize=` | Постраничный список `{items,totalCount,page,pageSize,totalPages}`; `from/to` — по дате корректировки, pageSize 1..100 (default 20). Поля пакета: `errors`, `appliedByUserId`, `appliedByName`, `appliedAt` |
| GET | `/{id}` | Пакет с позициями и ошибками (для `Draft` ошибки считает движок) |
| PUT | `/{id}` | Смена даты пакета (неделя/день пересчитываются для позиций); для применённого — `409` |
| DELETE | `/{id}` | Удалить пакет; применённый перед удалением откатывается вместе с записями журнала |
| DELETE | `/applied` | Удалить все применённые пакеты разом |
| POST | `/{id}/positions` | Добавить позицию. `changeType` — `Add` или `Remove`; значения `Replace`/`Move` приводятся к `Add`. `numberPair` и `removedNumberPair` — 1–7, иначе `400` |
| PUT | `/{id}/positions/{positionId}` | Изменить позицию (те же правила) |
| DELETE | `/{id}/positions/{positionId}` | Удалить позицию |
| POST | `/import` | Импорт XLSX (multipart, ≤10 МБ). Best-effort: при строчных ошибках пакет создаётся, возвращаются `batchId` и `errors`; без пакета — только структурные ошибки (нет даты/шапки) |
| POST | `/{id}/export` | XLSX с именем `Корректировка_ddMM.xlsx` (дата корректировки); преподаватель с инициалами; колонка «Примеч.» сохраняет служебные слова (`вм.X`, `сам.р`, `сам.р+`, `снять`). Перенос (`вм.X`) пишется только примечанием — колонки «снимается» пустые, потому что вводимое занятие само переезжает; замена заполняет обе колонки. Оформление задаётся кодом для всех строк: Times New Roman 12, рамка по периметру таблицы (средняя) и тонкие линии внутри |
| POST | `/{id}/apply` | Транзакционное применение; заголовок `Idempotency-Key`; пустой пакет → `400`; ошибки → `400` списком «Строка N: …»; повторный apply → `409` |

Флоу веб-редактора:

1. `POST /batches` либо `POST /batches/import`.
2. `GET /api/schedule/correction/references?groupId=&date=&batchId=&excludePositionId=` — справочники пошаговой формы: эффективное расписание группы на дату (те же `entries[]`, что у `/correction/day`, включая `informational: true` для пар «только информация») **плюс** `teachers[]` — преподаватели этой группы с их предметами именно в ней (`subjects` из базового расписания группы, применённых изменений и снятых записей; дубли схлопываются по ключу предмета). Форма берёт списки только отсюда, поэтому выбрать преподавателя или предмет, которых у группы нет, невозможно.
3. Позиции редактируются через `/positions`; список позиций постраничный на клиенте (20 на страницу) с фильтрами по группе и операции (добавление / снятие).
   `excludePositionId` исключает редактируемую позицию из наложения: иначе её собственный
   слот возвращался занятым и перенести пару на другой слот было нельзя.
4. `GET /batches/{id}` — проверка `errors` (сообщения «Строка N: …»).
5. `POST /batches/{id}/apply` → `{ applied, batchId, history }`.
6. `POST /batches/{id}/export` — XLSX (автоскачивание в UI).

Подтверждение применения и удаления — модальное окно с лоадером внутри кнопки: операция долгая (транзакция, рассылка в Max, генерация PNG), повторный клик заблокирован.

Журнал: `GET /api/schedule/history?week=&date=&from=&to=&changeType=&groupId=&teacherId=&page=&pageSize=` — `date` преобразуется в `week + день недели`, `from/to` — по `AppliedAt`, pageSize 1..100 (default 20), сортировка `AppliedAt DESC`; `teacherId` матчит текущего **или** снятого преподавателя.

Откат применённой корректировки: `DELETE /api/schedule/history/{historyId}` — роли `Dispatcher`, `Admin`. Возвращает `{ historyId, changeType, groupName, dayOfWeek, week, scheduleChanged, message }`. Логика отката по типам:

| Тип | Что делает откат |
|-----|-----------------|
| `Add` | убирает неделю из созданной пары; если недель не осталось — удаляет пару. Если в записи есть `RemovedSubject` (замена или перенос) — возвращает это занятие на `RemovedNumberPair` (или на `NumberPair`, если поле пустое) с `RemovedTeacherId`/`RemovedRoom` |
| `Remove` | возвращает неделю в пару; если пары нет (расписание перезагружали) — создаёт её заново по данным журнала |
| `Replace`, `Move` | записи, созданные до объединения операций: снимают добавленное и возвращают исходное как раньше |

Запись журнала удаляется в любом случае. `scheduleChanged: false` — пара уже была изменена или удалена другим способом, откат тронул только журнал. `сам.р` без «+» расписание не менял: откат чистит только запись. Откат необратим: в UI подтверждается модальным окном, кнопка «Откатить» в строке журнала.

Справочник: `GET /api/schedule/subjects?teacherId=&q=` — предметы для выпадающих списков (записи расписания + история преподавателя).

### 5.3. Уведомления и картинка (после apply, fail-safe)

- `MaxBotHttpClient.SendChangesAsync` → `POST /notify` бота Max. `ChangeNotifier` отправляет одно агрегированное сообщение на чат; преподаватель-получатель матчится по `TeacherName` **или** `RemovedTeacherName` — снятый преподаватель тоже получает уведомление.
- В дайджест добавляется пометка «🟣 Сам.р.» при самостоятельной работе и «🟣 Сам.р. (только информация)», если пара не вставала в расписание (`сам.р` без «+»).
- `CorrectionImageService.Render` (QuestPDF, `RasterDpi = 144`, высота по числу строк) рендерит PNG-таблицу; `MaxBotHttpClient.SendCorrectionImageAsync` → `POST /notify/correction-image`; бот грузит `POST /uploads?type=image` и отправляет изображение в канал `MaxBot:CorrectionChannelId` (`MaxBot__CorrectionChannelId` в compose / `MAX_CORRECTION_CHANNEL_ID`).
- Пустой `CorrectionChannelId` → warning в логах и пропуск. Сбой уведомления или картинки не откатывает применение.

Ошибки: `400` — невалидные данные, `401` — не авторизован, `403` — не диспетчер/админ, `404` — не найдено, `409` — неверный статус или повторный apply.

## 6. Требования к реализации

- `Result<T>` без try-catch в контроллерах/сервисах; `ExceptionHandlerMiddleware` — неожиданные ошибки.
- Валидаторы FluentValidation, сообщения на русском, Swagger-документация + Postman-коллекция.
- GUID PK `ValueGeneratedNever()`, enum `HasConversion<string>()`, `AsNoTracking()` на чтении, транзакции — применение.
- XLSX: ClosedXML. Уведомления: агрегация по получателю в MaxBot (`correction_date`, digest «дата + все позиции»).
- Максимум покрытия тестами: unit (валидация, «сам.р.», агрегация) + интеграционные (WebApplicationFactory).

## 7. Критерии приёмки

- [ ] Ручное создание: дата → неделя/день; **две операции — добавить и снять**; слоты 1–7; занятый слот не блокируется.
- [ ] «Добавить» в занятый слот спрашивает, что делать: «в параллель» (прежнее остаётся) или «заменить» (прежнее снимается одной транзакцией).
- [ ] `сам.р` — сама пара в базу расписания не встаёт, но видна в расписании дня и недели с бейджем «Сам.р.», слот свободен; в журнале есть запись.
- [ ] `сам.р+` — пара встаёт в расписание и помечается самостоятельной работой.
- [ ] `вм.X` предлагает только пары, где у вводимого преподавателя стоит этот же предмет; при расхождении — ошибка позиции, а не молчаливое снятие чужого занятия.
- [ ] `сам.р` совмещается с заменой и `вм.X`: снятия выполняются, сама пара остаётся пометкой.
- [ ] Замена с переносом даёт две записи журнала: «добавлено» и «снято».
- [ ] В карточках изменений и на парах расписания только два исхода: «Добавлено» и «Снято»; замена показывается как «старое => новое», перенос — как «пара X → Y».
- [ ] Импорт XLSX (best-effort): при строчных ошибках пакет создаётся и возвращает `batchId` + `errors`; без пакета — только структурные ошибки; позиции пакета только `Add`/`Remove`.
- [ ] Редактирование позиций в пакете; смена даты пакета до применения; выгрузка XLSX с ФИО с инициалами и колонкой «Примеч.» без потерь (`вм.X`, `сам.р`, `сам.р+`, `снять`).
- [ ] Порядок шагов одинаков у обеих операций; пара выбирается один раз; высота модального окна при смене операции не меняется; у готовой позиции виден итог одной фразой.
- [ ] Применённый пакет удаляется с откатом расписания (включая возврат заменённого занятия); «Очистить применённые» убирает все разом.
- [ ] Применение с подтверждением; транзакционно; `400` со списком «Строка N: …»; `409` на повторный apply; автоскачирование XLSX.
- [ ] Уведомление Max: одно сообщение на получателя (дата + все его позиции) только для выбранных текущими, включая снятого преподавателя; пометка самостоятельной работы; настройка при старте бота, по умолчанию 07:30.
- [ ] PNG-картинка корректировки публикуется в канал `MaxBot:CorrectionChannelId`; пустой канал и сбои — fail-safe.
- [ ] Старые пакеты и записи журнала с типами `Replace`/`Move` по-прежнему применяются и откатываются.
- [ ] `dotnet build`, `dotnet test`, `npx tsc --noEmit`, `docker compose up --build` проходят.
