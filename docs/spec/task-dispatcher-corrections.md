# ТЗ: Диспетчер — Корректировки расписания (пакетная модель)

> **Формулировка по факту реализации.** Изначально задача задумывалась для
> мини-приложения в боте Max, по итогам основная реализация выполнена на вебе
> (раздел **Диспетчер → Корректировки**). Дублирующая ручная форма доступна в
> мини-приложении Max (`max/DispatcherManual`), уведомления — через бота Max.

## 1. Цель

Дать диспетчеру инструмент подготовки и применения корректировок расписания:
ручное создание позиций (добавление/замена/снятие/перенос), импорт готового
XLSX, редактирование, применение с обязательным подтверждением и уведомлением
затронутых групп и преподавателей в мессенджере Max.

## 2. Область и роли

- Раздел **Диспетчер → Корректировки** (веб): вкладки **Пакеты / Редактор / Импорт / Журнал**.
- Роли: `Dispatcher`, `Admin`.
- Смежные модули: `ScheduleService` (расписание, применение), MaxBot (уведомления), хранилище файлов (XLSX).

## 3. Модель данных

| Сущность | Назначение | Ключевые поля |
|---|---|---|
| `CorrectionBatch` | Пакет корректировки на дату | дата, неделя, день недели, статус, создатель, применивший, `AppliedAt`, список позиций |
| `CorrectionPosition` | Одна позиция пакета | тип (Add/Remove/Replace/Move), группа, день, неделя, № пары, предметы/преподаватели (текущий и снимаемый), примечание, статус, `HistoryId` |

Статусы пакета: `Draft` (отображается как **«Подготовлен»**) → `Applied` (**«Применён»**) → `Cancelled` (**«Отменён»**).
На уровне API/БД используются значения `Draft/Applied/Cancelled`; русские подписи — только в UI.

## 4. Функциональные требования

### 4.1. Ручное создание корректировки

1. Начало работы — выбор **даты**. По умолчанию — текущая дата.
2. По дате автоматически определяются **номер недели** и **день недели**.
3. Типы позиций: **добавление, замена, снятие, перенос**.
4. Позиция **«Снять»**:
   - выбор группы из **поиска по базе**;
   - показ **расписания группы на выбранную дату**;
   - выбор, какую пару снять (только существующая пара группы на эту дату/неделю).
5. Поле **«Примечание»** — необязательное, заполняется по специальным соглашениям (чипы-подсказки над полем: «сам.р.», «замена», «перенос»).

### 4.2. Соглашение «сам.р.»

- Если в примечании стоит **`сам.р.`**:
  - допустимо **только для снятия (Remove)**; для остальных типов — ошибка валидации `400`;
  - при применении пара **не удаляется из базы** (запись и неделя сохраняются);
  - пара участвует в учебном процессе, но студентам показывается бейдж **«Самостоятельная работа»** — они могут не приходить;
  - для пары формируется запись журнала с пометкой «сам.р.», бейдж показывается в расписании/журнале.
- Если в поле примечания **не** стоит `сам.р.` — пара фактически снимается и **удаляется из базы** (снимается неделя; при снятии последней недели удаляется занятие целиком).

### 4.3. Импорт файла XLSX

1. Диспетчер загружает файл `.xlsx` (до 10 МБ).
2. Файл проходит **валидацию данных**; при ошибках показывается подробный список: `Строка N, стлб. M: сообщение`.
3. Соглашения импорта:
   - пара **снимается**, если заполнены только поля «Снимается по расписанию: Предмет» и «Преподаватель»;
   - если в примечании `сам.р.` — действует соглашение 4.2: пара не удаляется, получает бейдж.
4. При успешной валидации создаётся **пакет** (`batchId` в ответе) со списком всех позиций.
5. Каждую позицию можно **просматривать, редактировать, удалять, добавлять**. Хранение — отдельная сущность в БД (`CorrectionBatch`/`CorrectionPosition`).
6. Скачивание XLSX с **актуальными данными после редактирования**; к имени скачанного файла добавляется **postfix-timestamp**.

### 4.4. Применение корректировки

1. Когда пакет готов — кнопка **«Применить»**.
2. Обязательно **подтверждение** выбора (диалог).
3. Применение **транзакционное**: при ошибке — `400`, частичных изменений нет.
4. Повторный apply — `409` (пакет уже применён). Идемпотентность — заголовок `Idempotency-Key`.
5. После успеха: пакет → **«Применён»**, позиции → «Применён» + ссылка на запись журнала; данные расписания обновлены в БД.
6. После применения **автоматически скачивается XLSX**.
7. **Уведомления в мессенджере Max**: все группы и преподаватели из корректировки получают уведомление, если они **выбраны текущими** (подписаны). Уведомление содержит **дату и все позиции** корректировки, относящиеся к получателю (агрегированное, одно сообщение на получателя).
8. **Настройка уведомлений** — при старте бота через меню кнопок. По умолчанию время уведомлений — **7:30 утра**.

### 4.5. Журнал корректировок

- Вкладка «Журнал» показывает историю применённых изменений с фильтром по неделе и пагинацией; для записей «сам.р.» — бейдж «Самостоятельная работа».

## 5. API (REST, `/api/schedule/correction/batches`)

| Метод | Путь | Описание |
|---|---|---|
| POST | `/` | Создать пакет по дате (`400` — нет даты / выходной / вне семестра) |
| GET | `/?status=` | Список пакетов (по умолчанию — подготовленные) |
| GET | `/{id}` | Пакет с позициями |
| DELETE | `/{id}` | Удалить пакет (только «Подготовлен», иначе `409`) |
| POST | `/{id}/positions` | Добавить позицию |
| PUT | `/{id}/positions/{positionId}` | Изменить позицию |
| DELETE | `/{id}/positions/{positionId}` | Удалить позицию |
| POST | `/import` | Импорт XLSX (multipart); `batchId` в ответе; ошибки по строкам |
| POST | `/{id}/export` | Скачать XLSX пакета (имя с timestamp) |
| POST | `/{id}/apply` | Применить (заголовок `Idempotency-Key`; `409` повторный apply) |

Ошибки: `400` — невалидные данные, `401` — не авторизован, `403` — не диспетчер/админ, `404` — не найдено, `409` — неверный статус.

## 6. Требования к реализации

- `Result<T>` без try-catch в контроллерах/сервисах; `ExceptionHandlerMiddleware` — неожиданные ошибки.
- Валидаторы FluentValidation, сообщения на русском, Swagger-документация + Postman-коллекция.
- GUID PK `ValueGeneratedNever()`, enum `HasConversion<string>()`, `AsNoTracking()` на чтении, транзакции — применение.
- XLSX: ClosedXML. Уведомления: агрегация по получателю в MaxBot (`correction_date`, digest «дата + все позиции»).
- Максимум покрытия тестами: unit (валидация, «сам.р.», агрегация) + интеграционные (WebApplicationFactory).

## 7. Критерии приёмки

- [ ] Ручное создание: дата → неделя/день; доступны все 4 типа позиций; «Снять» через расписание группы на дату.
- [ ] «сам.р.» даёт бейдж «Самостоятельная работа» и не удаляет пару/неделю; вне Remove — `400`.
- [ ] Без «сам.р.» снятие удаляет пару из расписания.
- [ ] Импорт XLSX: ошибки построчно; успех создаёт пакет с позициями и возвращает `batchId`.
- [ ] Редактирование позиций в пакете; выгрузка XLSX с timestamp.
- [ ] Применение с подтверждением; транзакционно; `409` на повторный apply; автоскачивание XLSX.
- [ ] Уведомление Max: одно сообщение на получателя (дата + все его позиции) только для выбранных текущими; настройка при старте бота, по умолчанию 07:30.
- [ ] `dotnet build`, `dotnet test`, `npx tsc --noEmit`, `docker compose up --build` проходят.
