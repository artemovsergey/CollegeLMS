# ТЗ: Расписание — ручной CRUD и импорт XLSX (UC-SCH-06/07/08)

> **Формулировка по факту реализации.** Документ описывает изменения ручного редактирования
> расписания и импорта XLSX, реализованные коммитами `13fff01` (время из звонков, недели,
> пересечения по неделям), `78905ac` (парсер: пары 1–8, полные ошибки, превью с записями),
> `11eb083` (confirm: повторная валидация, курс групп, преподаватели без дублей, отчёт) и
> `dc9b904` (диалоги фронтенда). Источник: код `CollegeLMS.API/`, `CollegeLMS.Next/`, спека
> `docs/superpowers/specs/2026-09-21-schedule-crud-import-design.md`.

## 1. Цель

Закрыть требования эталонного ТЗ по ручному редактированию расписания и импорту XLSX
(`docs/spec/task-schedule-management.md`, UC-SCH-06/07/08): единый источник времени пар —
справочник звонков; валидация недель семестра; пересечения с учётом недель; полный список
ошибок разбора с адресом «лист, строка, столбец»; строгий `confirm` с повторной валидацией,
транзакционной заменой и отчётом.

## 2. Роли

| Роль | Права |
|---|---|
| `Dispatcher`, `Admin` | `POST/PUT/DELETE /api/schedule`, `POST /api/schedule/import/preview`, `POST /api/schedule/import/confirm` |
| `AllowAnonymous` | `GET /api/schedule/{id}`, `GET /api/schedule`, `GET /api/bells` (источник времени) |
| Все авторизованные | просмотр расписания (виды day/week/semester/calendar) |

## 3. Модель данных

Схема БД **не менялась** (миграций нет). `ScheduleEntry` (`schedule_entries`): `GroupId`,
`TeacherId?`, `Subject`, `Room`, `DayOfWeek`, `NumberPair` (1–8), `Weeks` (`int[]`),
`StartTime`/`EndTime`, `LessonType`. Время хранится в записи, но при записи всегда вычисляется
сервером из справочника звонков, а при чтении подменяется им же.

## 4. API (REST)

### 4.1. Ручной CRUD — `/api/schedule` (ломающее изменение контракта)

| Метод | Роль | Тело / ответ |
|---|---|---|
| `POST /api/schedule` | Dispatcher/Admin | `CreateScheduleRequest { groupId, teacherId?, subject, room, dayOfWeek, numberPair, weeks[], lessonType }` → `Result<ScheduleResponse>` |
| `PUT /api/schedule/{id:guid}` | Dispatcher/Admin | `UpdateScheduleRequest` — тот же состав → `Result<ScheduleResponse>` |
| `GET /api/schedule/{id:guid}` | AllowAnonymous | `Result<ScheduleResponse>` |
| `DELETE /api/schedule/{id:guid}` | Dispatcher/Admin | `Result` |

- **Полей `startTime`/`endTime` в запросах больше нет**: сервер игнорирует любое клиентское
  время и берёт его из `IBellScheduleService.GetTimeMapAsync` по `numberPair`
  (fallback — `ScheduleImportService.GetPairTime(day, pair)`, см. §5.1 и §9).
- Ответы `Create/Update/GetById/GetAll` всегда содержат время из справочника звонков
  (подмена как в `GetAllAsync`).
- Валидации `400`: `subject` не пустой и ≤200; `room` не пустой и ≤50; `groupId` задан;
  `numberPair` 1–8; `weeks` не пусты и в диапазоне `1…TotalWeeks` (16); `lessonType` ∈
  {`None`, `Lecture`, `Practice`, `Lab`, `Exam`}. Валидаторы `StartTime < EndTime` удалены.
- `404` — запись/группа/преподаватель не найдены; `409` — пересечение (см. §5.3).
- Недели дедуплицируются и сортируются в сервисе.

### 4.2. Превью импорта — `POST /api/schedule/import/preview`

| Аспект | Поведение |
|---|---|
| Формат | multipart/form-data, поле `file`; Dispatcher/Admin |
| Ограничения FILE-1 | только `.xlsx`, ≤10 МБ; иначе `400` |
| Успех | `200` `Result<SchedulePreviewResponse> { totalEntries, entries[], errors[] }`; **записи и ошибки могут вернуться вместе** |
| Ошибки разбора | `200` (не `400`): распознанные позиции попадают в `entries`, ошибки — в `errors` |

`400` остаётся только для FILE-1: «Файл не выбран», «Поддерживается только формат XLSX»,
«Файл слишком большой. Максимум 10MB.» (тело `Result<T>`) и «Не удалось прочитать файл.
Убедитесь, что это XLSX-файл.» (сырое тело `PreviewResult` — см. §9).

### 4.3. Подтверждение — `POST /api/schedule/import/confirm`

Тело — **сырой** `ConfirmImportRequest { entries: SchedulePreviewEntry[] }` (поля как в превью;
`startTime`/`endTime` игнорируются и пересчитываются).

- Позиции повторно валидируются: пара 1–8, недели `1…TotalWeeks`, корректный день недели,
  непустые `groupName`/`subject`/`room`.
- Ошибки → `400` с **сырым** `ConfirmResult` (не `Result<T>` — отклонение от соглашений,
  см. §9): `{ isSuccess: false, imported: 0, groups: 0, teachers: 0, schedule: [], errors: [] }`.
- Пустой список → `400` с ошибкой уровня `structure`: «Нет позиций для импорта».
- Успех → `200` с сырым `ConfirmResult`: `{ isSuccess: true, imported, groups, teachers,
  schedule[], errors: [] }`, где `groups`/`teachers` — количество **созданных** записей.
- Полная замена расписания в одной транзакции: удаляются все `schedule_entries` и
  `schedule_history`, затем вставляются позиции импорта; при сбое — `ROLLBACK` и `500`.

### 4.4. Формат ошибок валидации

```json
{ "sheet": "Лист1", "row": 9, "column": 4, "level": "data",
  "message": "Лист Лист1, строка 9, столбец 4: неделя 17 вне семестра (1–16)" }
```

- `level = "structure"` — лист/шапка/дни/файл; `level = "data"` — ошибки ячеек.
- `message` формируется сервером целиком, с префиксом «Лист {имя}, строка N, столбец M: …»;
  фронт выводит его как есть (двойной префикс удалён).
- Для confirm-ошибок `sheet = "импорт"`, `row` = индекс позиции + 2, `column = 0`.
- При структурной ошибке без адреса (`row = 0`) префикс по-прежнему формируется.

## 5. Правила

### 5.1. Время пар — единый источник

1. `CreateAsync`/`UpdateAsync`/`ParseScheduleMatrix`/`ConfirmAsync` вызывают
   `GetTimeMapAsync` и берут время по `NumberPair`.
2. Если пары нет в справочнике — fallback `GetPairTime(day, pair)`: легаси-слоты по дням
   (понедельник — 6 пар, вторник/среда/пятница — 7, четверг — 6, суббота/воскресенье —
   как вторник); номер пары клампится к последнему слоту.
3. Поведение корректировок, дашборда и экспорта не изменилось (`GetPairTime` сохранён).
4. Фронт не редактирует время: `ScheduleEntryDialog` показывает вычисленное
   «08:30–09:50 · из справочника звонков» по данным `GET /api/bells` и пересчитывает его
   при смене номера пары.

### 5.2. Недели

- Диапазон `1…StudyWeek.TotalWeeks` (сейчас 16; старт семестра 01.09.2026).
- Дедупликация и сортировка перед сохранением; пустой список → `400`
  «Укажите хотя бы одну неделю» / «Недели должны быть в диапазоне 1–16».
- В импорте недели читаются из скобок ячейки (одиночные «5» и диапазоны «1-8», через запятую),
  вне семестра → ошибка данных «неделя N вне семестра (1–16)», пустые → «не указаны недели».

### 5.3. Пересечения (только ручной CRUD)

- Кандидаты: тот же день + номер пары + совпадение группы, преподавателя или аудитории.
- Затем в памяти проверяется пересечение недель (`Weeks.Intersect(weeks).Any()`) —
  `409` только при реальном пересечении недель; занятия в непересекающиеся недели разрешены.
- Сообщения: «У группы уже есть занятие в эту пару», «У преподавателя уже есть занятие
  в эту пару», «Аудитория уже занята в эту пару».
- `UpdateAsync` исключает собственную запись (`excludeId`).

### 5.4. Полная замена (импорт)

- `confirm` доверяет файлу: пересечения и дубликаты в файле не проверяются — расписание
  заменяется целиком (см. §9).
- Группы: поиск по имени, иначе создание; `Course` — первая цифра имени, кламп 1–4
  (ИС-21 → 2, 1-11 → 1, без цифр → 1).
- Преподаватели: поиск `User` роли Teacher по канонизированному ФИО; при наличии `User` без
  `Teacher`-профиля профиль создаётся; иначе создаются `User` + `Teacher`. Дубли `User`
  по одному ФИО не создаются.
- `LessonType` импортированных пар — `None`.

## 6. Нормализация

- **Предметы** — словарь `SubjectSynonyms` (regex, регистронезависимый) в
  `ScheduleImportService`: например `Физ.культура`/`Физ.кул.` → `Физкультура`,
  `Ист.Р.` → `ИсторияРоссии`, `Матем.` (кроме `Математики`) → `Математика`,
  `Охр.тр.`/`Охрана труда` → `ОхранаТруда`, `Электр.*`/`Эл.тех.` → `ЭлектрТех.`,
  `Электробез.` → `ЭлектрБезопасность`.
- **ФИО преподавателя** — `NormalizeTeacherName`: trim, схлопывание пробелов, нормализация
  точек в инициалах («И. И.» → «И.И.»); сравнение при confirm — по канонизированному ключу.
- **Ячейка** — «аудитория предмет (недели) преподаватель»; поддержаны маркеры `ч.з`/`с.з`
  (недели в скобках, аудитория — первый токен) и лабораторные пометки; у пары может быть
  несколько предметов (несколько строк под номером пары).
- Словарь — в коде (не таблица-справочник в БД); незнакомые сокращения остаются как есть.

## 7. Фронтенд

- `ScheduleEntryDialog`: поля `type="time"` удалены; показывается вычисленное время из
  справочника звонков (`fetchBells`), пересчёт при смене пары; недели валидируются по
  `totalWeeks` из `fetchScheduleMeta()` (диапазон, placeholder, ошибка под полем).
- `ScheduleImportDialog`: шаги «upload → preview → result»; «Просмотр» → preview; ошибки
  (превью + confirm) выводятся единым списком, кнопка «Загрузить» блокируется при непустом
  списке ошибок; отчёт «Загружено пар: N · Группы: M · Преподаватели: K» и тост; сырое тело
  `400` обрабатывается как `ScheduleImportError` (данные из `err.response.data`) без
  дублирующего префикса.
- Страница `/schedule`: передаёт `totalWeeks` из meta в диалоги.

## 9. Известные ограничения

- **Сырое тело confirm.** `POST /api/schedule/import/confirm` возвращает `ConfirmResult` без
  обёртки `Result<T>` и на `200`, и на `400` — сознательное отклонение от общего соглашения,
  нужно фронту для отображения отчёта/ошибок одним объектом. Аналогично `400` «нечитаемый
  файл» у preview отдаёт сырой `PreviewResult`, тогда как FILE-1-проверки контроллера —
  `Result<T>`; фронт обрабатывает оба случая.
- **Fallback-слоты.** `GetPairTime` — легаси-расписание по дням (понедельник — 6 пар, суббота
  и воскресенье — по сетке вторника), номер пары клампится; используется только когда пары
  нет в справочнике звонков. При заполненном справочнике (сиды: 8 пар 08:30–09:50 …
  19:35–20:55) fallback не срабатывает.
- **`Enum.TryParse` для дня недели.** Confirm проверяет `entry.Day` через
  `Enum.TryParse<DayOfWeek>(day, true, …)`: проходят английские имена в любом регистре,
  а также **числовые строки**, включая вне диапазона 0–6 (например, `"7"`); отвергается
  только нераспознанный текст. Preview отдаёт `day.ToString()` (`"Monday"`).
- **Импорт не проверяет пересечения** и дубликаты: файл замещает расписание целиком, что
  соответствует полной замене; ошибочный файл может создать дубли пар.
- **CFG-1.** Семестр остаётся на константе `StudyWeek` (старт 01.09.2026, 16 недель); вынос
  в конфигурацию — отдельная итерация.
- **Нормализация** ограничена словарём в коде; неизвестные сокращения предметов не
  исправляются.
