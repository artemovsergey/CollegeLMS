# Дизайн-спецификация: бот Max и мини-приложение — завершение

**Дата:** 2026-09-21
**Статус:** утверждена пользователем (секции в чате, 2026-09-21)
**Цель:** закрыть оставшиеся требования эталонного ТЗ по боту Max и мини-приложению: онбординг и защита диспетчерского режима, слои расписания в недельном виде, отправка XLSX файлом в каналы, идемпотентная ежедневная рассылка, безопасный диспетчерский экран мини-приложения.

**Источник требований:** `docs/spec/task-schedule-management.md` — UC-SCH-36, UC-SCH-37, UC-SCH-38, UC-SCH-40, UC-SCH-43 (+ UC-SCH-27 в части автоскачивания в мини-приложении).

## 1. Границы итерации

### 1.1. Входит

| UC | Состав работ |
|----|--------------|
| UC-SCH-37 | Онбординг `/start` (роль → группа/преподаватель → подтверждение); rate limit входа диспетчера по паролю |
| UC-SCH-38 | Недельный вид бота через серверный `view=week` со слоями; лимит календаря по `totalWeeks` из `/api/schedule/meta`; различение ошибки и пустого ответа, кнопка «Повторить» |
| UC-SCH-40 | XLSX в каналы whitelist отправляется файлом (`type=file`) с inline-кнопкой; «вм.X» — серверный автофилл вместо клиентского |
| UC-SCH-43 | Мини-апп: смонтирован `DispatcherGate`; подтверждение перед применением импорта; автоскачивание XLSX после применения |
| UC-SCH-36 | Дайджест: источник `view=day`; идемпотентность в БД бота (`last_notified_on`); гард «группа/преподаватель не выбраны» |

День в боте также переводится на `view=day` — единый источник слоёв (устраняет три параллельных запроса practices/schedule/inserts).

### 1.2. Не входит

- **CFG-1** (семестр в конфигурацию) — отдельная итерация «Инфраструктура»; в боте лимит календаря берётся из meta API, константа `StudyWeek` остаётся fallback.
- **Избранное** (UC-SCH-39/42), **CRUD/импорт расписания** (UC-SCH-06/07/08).
- **UC-SCH-35** — уже реализован в боте; в мини-приложении настроек уведомлений нет (по ТЗ их там быть не должно).
- Веб `/schedule`, API-контракты и схема основной БД не меняются.

### 1.3. Принятые отклонения

- Доступ к диспетчерскому режиму мини-приложения — по паролю диспетчера: контекст мини-приложения (`/api/schedule/context`) различает только Student/Teacher/Other и не отдаёт роль Dispatcher/Admin, поэтому используется ветка ТЗ «либо после ввода пароля диспетчера».
- При наличии файла Max API требует вложение-клавиатуру: к XLSX прикладывается кнопка-ссылка `link` «📥 Скачать XLSX» (прямой URL выгрузки через мини-апп-прокси), вместо чистого файла.

## 2. Онбординг и защита диспетчера (UC-SCH-37)

### 2.1. Поток `/start`

1. `/start` (или `/help`) у пользователя без настроенной группы и преподавателя:
   - приветствие «👋 Привет! Я бот расписания.» + выбор роли («🎓 Студент» / «👨‍🏫 Преподаватель») — payload `onboard:role:student|teacher`;
2. После роли:
   - студент → список групп (`onboard:group` / страницы / поиск — переиспользование существующего выбора групп);
   - преподаватель → список преподавателей с поиском (`onboard:teacher`);
3. После выбора — подтверждение («Готово! Группа: …» / «Готово! Преподаватель: …») и главное меню.
4. Пользователь с настроенной группой/преподавателем: `/start` → сразу главное меню.

Существующие настройки (`/settings`, payload `settings:group|teacher`) сохраняют поведение: после выбора возврат в «Настройки».

### 2.2. Rate limit пароля диспетчера

- Счётчик неудачных попыток на пользователя (in-memory): после **5** неверных паролей — блок **15 минут** с сообщением «❌ Слишком много попыток. Повторите через N мин.».
- Успешный вход сбрасывает счётчик; блокировка истекает по времени.
- API `/api/dispatcher/login` продолжает лимитировать по IP (без изменений).

## 3. Расписание в боте (UC-SCH-38)

### 3.1. День

- Источник — `GET /api/schedule?view=day&date=…&groupId=|teacherId=` (новый метод клиента бота).
- Отображение из DTO: практика заменяет пары (карточка УП/ПП), вставки — отдельные строки `HH:mm–HH:mm Название`, нерабочий день — «🎉 Нерабочий день: {название}», воскресенье — «Расписания нет — выходной!»; пары с бейджами корректировок («сам.р.» и др.).
- Формат сообщений сохраняется (иконки типов, время, аудитория, группа у преподавателя).

### 3.2. Неделя

- Источник — `GET /api/schedule?view=week&week=N&groupId=|teacherId=`.
- Для каждого дня Пн–Сб: практика (заменяет пары), вставки, нерабочий день, пустой день — «Пар нет.»; заголовок «📅 Неделя NN · dd.MM–dd.MM».
- Длинные сообщения по-прежнему разбиваются на части (заголовок + сообщения по дням).

### 3.3. Календарь

- Верхняя граница навигации — `semesterStart + totalWeeks` из `GET /api/schedule/meta` (fallback — константа `StudyWeek`, если meta недоступен).

### 3.4. Ошибки

- Клиент различает: (а) ошибка запроса (сеть/5xx/невалидный ответ) и (б) валидный пустой результат.
- При ошибке — сообщение «❌ Не удалось загрузить расписание.» + inline-кнопка «🔄 Повторить» с тем же контекстом (дата/неделя, день/неделя/календарь).

## 4. Диспетчер в боте (UC-SCH-40)

### 4.1. XLSX файлом

- `POST /uploads?type=file` → абсолютный URL загрузки; загрузка multipart (поле `data`, имя файла, `Content-Type` XLSX), ответ содержит `token`.
- Отправка: `POST /messages?chat_id={target}` с `attachments`:
  - `{ "type": "file", "payload": { "token": … } }`,
  - `{ "type": "inline_keyboard", … }` — кнопка `link` «📥 Скачать XLSX» с URL `MiniAppUrlBuilder.BuildScheduleExportXlsxUrl(...)`.
- Обработка `attachment.not.ready` — повтор до 3 попыток с паузой 3 с (как у изображений).
- Текстовое сообщение-ссылка больше не отправляется; при сбое — сообщение об ошибке (fail-safe, корректировки не затрагиваются).

### 4.2. «вм.X»

- Бот не предзаполняет `Note` для переноса: сервер (`CorrectionBatchService.ResolveNote`) сам подставляет `вм.{RemovedNumberPair}`, когда примечание пусто.
- В предпросмотре визарда примечание переноса отображается из выбранной старой пары (или не отображается до применения).

## 5. Мини-приложение: диспетчерский экран (UC-SCH-43, UC-SCH-27)

- **Гейт:** `DispatcherView` при отсутствии `dispatcherToken()` рендерит `DispatcherGate` (ввод пароля → `dispatcherLogin` → режимы). После входа — режимы «Файл XLSX» / «Вручную». При `401/403` от диспетчерских API — `dispatcherLogout()` и возврат к гейту.
- **Подтверждение импорта:** перед `apply` файлового импорта — шторка «Применить N изменений?» с кнопками «Отмена» / «Применить»; ручной режим использует существующую `ConfirmOpsSheet`.
- **Автоскачивание XLSX (UC-SCH-27):** сразу после успешного применения — однократное автоматическое скачивание `Корректировка_dd.MM.yyyy_HH-mm-ss.xlsx`; кнопка ручного скачивания сохраняется.

## 6. Ежедневная рассылка (UC-SCH-36)

- **Источник** — `view=day` (практики и нерабочие учитываются сервером); текст — существующий формат дня (пары, время, аудитория, бейджи; практика заменяет пары).
- **Нерабочий день** — рассылка не отправляется (запись о дне не создаётся).
- **Гард:** `GroupId == null && TeacherId == null` → пользователь пропускается (ничего не отправляется).
- **Идемпотентность в БД:**
  - новое поле `UserSettings.LastNotifiedOn` (`DateOnly?`, колонка `last_notified_on DATE`);
  - идемпотентный `ALTER TABLE user_settings ADD COLUMN IF NOT EXISTS last_notified_on DATE;` в `Program.cs` (паттерн `EnsureCreated`);
  - отправка только если `LastNotifiedOn != today`; после успешной отправки — запись `today`;
  - in-memory словарь `_lastSentPerUser` удаляется.
- Окно ±15 минут и расписание времени (МСК) сохраняются.
