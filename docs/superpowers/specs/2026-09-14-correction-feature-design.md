# Функционал корректировок расписания: веб-форма, бот, данные — дизайн

> Утверждено пользователем 2026-09-14. Реализует 18 пунктов доработок после первого редизайна mini-app MAX.

## Контекст

- **Web** (`CollegeLMS.Next/components/ManualCorrectionForm.tsx`) — форма ручной корректировки для диспетчера в веб-версии (вкладка «Корректировки»).
- **Бот** (`CollegeLMS.Next/components/max/DispatcherManual.tsx`) — форма ручной корректировки в Telegram mini-app MAX.
- **Backend** — `ScheduleCorrectionService` (export/preview/confirm/history), `ScheduleService` (журнал, subjects), `ScheduleController`.
- Диспетчерский функционал доступен ролям `Dispatcher,Admin`.

## Общие ограничения

- Применение корректировок (confirm) — идемпотентно (`Idempotency-Key`), всё применение в одной транзакции.
- Списки групп/предметов/преподавателей приходят из БД, не хардкодятся.
- Сообщения об ошибках на русском. Все запросы через `lib/api.ts`.

## Часть A. Веб-форма ручной корректировки (пп. 1–9)

1. **Группа** — выбор из списка групп БД (NativeSelect). Уже реализовано.
2. **№ пары** — числовое поле 1–8. Уже реализовано (валидация в `generate`).
3. **Предмет** — «Снимается» и «Вводится»: выбор из списка предметов БД
   (`GET /api/schedule/subjects?q=`) вместо свободного текста.
4. **Преподаватель** — очищаемый выбор: пункт «Не указан», возможно пропустить
   (сейчас NativeSelect без пустого пункта).
5. **Примечание** — чипы-подсказки над полем: «сам.р.», «замена», «перенос»,
   подставляют текст в строку, повторный клик очищает.
6. **Добавление/удаление строк** — уже реализовано, сохранить.
7. **Кнопки действий**:
   - «Скачать XLSX» — формирует файл через `exportManualCorrection` и скачивает.
   - «Применить» (вместо «Скачать и применить») — формирует файл, показывает
     **модальное окно предпросмотра** операций (тип, группа, день, неделя,
     пара, предмет, преподаватель) и по подтверждению применяет
     через `confirmCorrection(preview.entries, uuid)`.
8. **Ошибки применения** — серверные ошибки показываются целиком
   (список ошибок) в модальном окне/тосте.

## Часть B. Backend (пп. 9–10)

9. **`GET /api/schedule/subjects?q=`** — возвращает `SubjectsResponse`:
   `List<string>` уникальных предметов (DISTINCT из `ScheduleEntries.Subject`
   + `ScheduleHistory.Subject` + `ScheduleHistory.RemovedSubject`),
   отфильтрованных по `q` (contains, case-insensitive), отсортированных,
   лимит ~200. `AllowAnonymous`, чтобы автокомплит работал во всех интерфейсах.
   Swagger-документация + Postman.
10. **Серверная валидация в `ConfirmAsync`** — перед применением проверить все
    `entries`:
    - для `Remove`/`Replace`/`Move` находит целевое занятие по тем же правилам,
      что `ApplyEntryAsync` (группа, день, пара, предмет, преподаватель, неделя);
    - при ошибках **не применять ничего**, вернуть `400` со списком сообщений
      (первая ошибка, аналог существующих ошибок уровня "semantic");
    - при успехе — применять как сейчас, но вместо `InvalidOperationException`
      собирать ошибки и прерывать до начала записи.

## Часть C. Бот (пп. 11–18)

11. **`DispatcherManual` — синхронизация UX с веб-формой**:
    - предмет — выбор из БД (`fetchSubjects`): ввод фильтрует список подсказок;
    - преподаватель — очищаемый (кнопка «Сбросить» уже есть);
    - примечание — чипы-подсказки (общий компонент с веб-формой);
    - **модальная форма подтверждения** (bottom sheet): список операций +
      кнопки «Применить» / «Отмена» перед `confirmCorrection`.
12. **Убрать дубль заголовка «Расписание»** на экране расписания — оставить
    один заголовок страницы.
13. **Выравнивание навигации** — иконка + подпись в `max-app__tab` по центру,
    на узких экранах без смещения (flex).
14. **Подпись поля поиска** — «Поиск» (в `SearchSheet`).
15. **Иерархия расписания** — стабильный порядок: неделя → день (Пн–Пт по
    возрастанию `dayOfWeek`) → пары по возрастанию номера; дубли заголовков
    дней исключены.
16. **Заголовок страницы «Изменения»** — отступы между заголовком, фильтром
    «Неделя» и списком (`.max-app__filter-row` margin-top).
17. **Пятая вкладка «Журнал»** — появляется в `MaxShell` только для роли
    `Teacher` (из `useMaxContext().profile`), ведёт на `/max/journal`
    (`JournalView` — уже существует).
18. **Бейджи корректировок в расписании** — `ScheduleResponse.changeTags`
    отображать чипом на строке пары в `DayFeed`/`WeekFeed`
    (компонент `components/max/ChangeBadge.tsx`, стили адаптированы из
    `ChangeTagBadge` для мобильного вида: короткая подпись, без tooltip —
    только подпись «+ Замена · нед.3»).

## Критерии приёмки

- [ ] `dotnet build` и `dotnet test` проходят.
- [ ] `npm run build` проходит.
- [ ] `GET /api/schedule/subjects` возвращает предметы, фильтрует по `q`, заполняет Postman.

      возвращает 400 со списком ошибок и ничего не применяет.
- [ ] Журнал бота: `JournalEntryItem` включает `dayOfWeek` и фактическую дату дня,
      показывает только проведённые занятия (дата ≤ сегодня).
- [ ] Веб-форма: предметы из БД, преподаватель очищаемый, чипы примечаний,
      модальное подтверждение перед применением.
- [ ] Бот: ручная форма с предметами из БД, чипы, модальное подтверждение;
      вкладка «Журнал» для преподавателя; бейджи корректировок в расписании;
      исправлены дубли/выравнивание/подписи/отступы (пп. 12–16).
