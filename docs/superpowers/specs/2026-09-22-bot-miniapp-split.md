# Разделение бота MAX и мини-приложения

Дата: 2026-09-22

## Контекст

Бот и мини-приложение дублировали функции: просмотр расписания и изменений,
пошаговый визард корректировок, XLSX-рассылка диспетчера, избранное в двух
местах. Пользовательские решения:

- в боте остаются только **уведомления** (настройка + доставка);
- в мини-приложении — **расписание, избранное, изменения**;
- **диспетчер** работает только в веб-приложении (роль Dispatcher);
- карточки изменений в мини-приложении — как в веб-версии;
- уведомления оформлены лаконично, «карточка-блок»;
- deep-link (start_param) внедряется сразу.

## Решение

### Бот (CollegeLMS.MaxBot)

- Главное меню: **🔔 Уведомления** и **⚙️ Настройки**.
- Экран уведомлений (`ShowNotificationsAsync`): статус, дни недели (toggle),
  время дайджеста ±5 минут (07:30–08:30), кнопка возврата в меню.
- Настройки: смена роли, группы/преподавателя.
- Удалены: просмотр расписания (день/неделя/календарь), «Мои изменения»,
  избранное (модель `BotFavorite` остаётся в схеме БД), диспетчер
  (команда `/dispatcher`, пароль-флоу, XLSX-рассылка, визард корректировок),
  `DispatcherCorrectionWizard`, `DispatcherLoginThrottle`, `CalendarFormatter`.
- `CollegeLmsApiClient` сокращён до групп, преподавателей, day/week view,
  нерабочих дней и практик.
- Формат `FormatCorrectionDigest` переписан в «карточка-блок»: тип, группа,
  день/неделя/пара, аудитория, «было → стало», преподаватель, примечание и
  строка `📱 Открыть: {MiniAppUrl}?route=day&date=...`.

### Мини-приложение (CollegeLMS.Next, /max)

- Диспетчер удалён полностью: страница, компоненты, клиент API, ветка
  `sessionStorage.dispatcherToken` в `lib/api.ts`, CSS-блоки.
- Карточка изменений переписана под веб-версию (`components/ChangeCard.tsx`):
  бейдж типа + «Сам.р.», полная дата, день и номер недели, группа, пара
  (с переносом), аудитория, зачёркнутый старый предмет → новый, преподаватель,
  примечание, «Применено», ссылка на день.
- MAX Bridge: скрипт `https://st.max.ru/js/max-web-app.js` в `app/max/layout.tsx`;
  `lib/max-context.tsx` читает `window.WebApp.initDataUnsafe.start_param`,
  применяет группу/преподавателя к контексту просмотра и переходит на нужный
  раздел; `lib/max-deeplink.ts` разбирает payload
  `{route}[-yyyy-MM-dd][-g-{groupId}|-t-{teacherId}]` и query-параметры.
- Бот формирует payload (`MiniAppUrlBuilder.BuildStartPayload`) с маркерами
  `g-`/`t-`, чтобы приложение отличало группу от преподавателя.

## Изменённые области

| Область | Файлы |
|---------|-------|
| Бот: меню/уведомления | `Bot/MaxBotService.cs` |
| Бот: формат | `Services/MessageFormatter.cs`, `Services/MiniAppUrlBuilder.cs` |
| Бот: чистка | `Clients/CollegeLmsApiClient.cs`, `MaxBotOptions.cs`, удалены сервисы диспетчера |
| Тесты бота | `CollegeLMS.MaxBot.Tests/*` (удалены тесты диспетчера/календаря, обновлены форматтеры и URL-builder) |
| Мини-апп | `app/max/**`, `components/max/{MaxShell,ChangeCard,ChangesView,ScheduleView}.tsx`, `lib/{max-context,max-deeplink,api}.ts`, `app/max/max.css` |
| E2E | `e2e/max-miniapp.spec.ts` |

## Проверки

- `dotnet build CollegeLMS.slnx`, таргетные тесты MaxBot (формат, подписки,
  вебхук, роль-флоу).
- `npm run build`, `npm run lint`, `npx playwright test max-miniapp.spec.ts`.
- Ручная проверка в MAX: меню из двух пунктов, настройка уведомлений,
  кнопка «Открыть» ведёт в мини-приложение на нужный раздел.

## Риски и последствия

- `bot_favorites` и `schedule_revisions` остаются в схеме БД (идемпотентный
  DDL не меняется), но бот их больше не использует — избранное мини-приложения
  локальное (по решению).
- XLSX-рассылка диспетчера удалена; выгрузка расписания доступна в веб-версии.
- В обычном браузере MAX Bridge отсутствует — используется fallback на
  query-параметры (`?route=...&date=...`).
