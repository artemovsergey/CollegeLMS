# Дизайн-спецификация: виды расписания и слои в веб и мини-приложении

**Дата:** 2026-09-21
**Статус:** утверждена пользователем (секции в чате, 2026-09-21)
**Цель:** реализовать четыре вида расписания (день, неделя, календарь месяца, семестр) с единым серверным слиянием слоёв — звонки, вставки, практики, нерабочие дни, бейджи корректировок — для веб-приложения и мини-приложения Max; экспорт дня и недели с теми же слоями и именованием FILE-3.

**Источник требований:** `docs/spec/task-schedule-management.md` (эталонное ТЗ) — UC-SCH-01, UC-SCH-02, UC-SCH-03 (веб-часть), UC-SCH-04, UC-SCH-05, UC-SCH-09, UC-SCH-14, UC-SCH-17, UC-SCH-41 (отображение слоёв).

## 1. Границы итерации

### 1.1. Входит

| Слой | Состав |
|------|-------|
| Backend | `ScheduleViewService`: структурированные виды `GET /api/schedule?view=day\|week\|semester\|calendar`; слияние слоёв на сервере; время из справочника звонков; бейджи корректировок |
| Экспорт | `GET /api/schedule/export?scope=day\|week` — `date`/`week`, слои, бейджи, FILE-3, `400`/`404` |
| Веб `/schedule` | 4 режима: «День», «Неделя», «Календарь», «Семестр»; состояние в URL; дефолт пользователя (студент → своя группа, преподаватель → сам); UI-1…UI-4 |
| Мини-приложение | Слои в существующих экранах «День» и «Неделя» (данные из `view=day\|week`) |
| Документация | Postman, PlantUML (Class, Sequence), пост-фактум ТЗ итерации |

### 1.2. Не входит

- **CFG-1** (семестр из конфигурации) — отдельная итерация «Инфраструктура». UI берёт `semesterStart`/`totalWeeks` из `GET /api/schedule/meta`, хардкод `2026-09-01`/`52` из фронтенда удаляется.
- **Бот Max** — недельный вид со слоями, лимит календаря по `TotalWeeks`, rate-limit пароля диспетчера (UC-SCH-37…40) — отдельно.
- **Мини-приложение**: новые режимы (календарь, семестр), синхронизация избранного (UC-SCH-42) — отдельно.
- Пробелы UC-SCH-06/07/08 (валидация недель семестра, пересечения с учётом недель, время из звонков при ручном CRUD, отчёт импорта, сверка confirm с превью) — отдельная итерация.
- `PAG-2` (pageSize ≤ 100), идемпотентность ежедневной рассылки, картинка/файлы в боте.
- E2E Playwright (как и в прошлых итерациях) — ключевые флоу проверяются вручную на трёх viewport'ах.

### 1.3. Известное расхождение с ТЗ

`UC-SCH-09` требует `AUTH-1` (только авторизованные) для экспорта. Текущий `GET /api/schedule/export` — `AllowAnonymous` (зафиксировано в `docs/spec/task-schedule-reference-data.md`). В этой итерации доступ не меняем (чтение расписания публично), веб-кнопка остаётся за авторизацией. Расхождение — кандидат на отдельное решение.

## 2. Архитектура

### 2.1. Компоненты

- **Новый** `CollegeLMS.API/Services/ScheduleViewService.cs`, интерфейс `Interfaces/IScheduleViewService.cs`, регистрация в `Extensions/ServiceCollectionExtensions.cs`.
- `ScheduleController.GetAll` диспетчеризует: `view=day|week|semester|calendar` → методы view-сервиса; иначе — текущий paged-список `ScheduleService.GetAllAsync`.
- **Экспорт дня/недели** (`ScheduleExportService`) собирает данные через `IScheduleViewService` — слои и правила не дублируются.
- Старые `CalendarResponse`/`CalendarDayResponse` и `IScheduleService.GetCalendarAsync` удаляются: после перехода веб-страницы на `view=semester` потребителей нет (бот и мини-приложение `view=calendar` не вызывают).
- Новый DTO-файл `Dtos/ScheduleViewDtos.cs`.
- Зависимости сервиса: `AppDbContext`, `IBellScheduleService` (время пар). Бейджи: приватный `ScheduleService.GetChangeTagsAsync` выносится в общий внутренний компонент (например, `Services/ScheduleChangeTags.cs`) и используется обоими сервисами — дублирование запрещено.

### 2.2. Канонические правила слоёв на дату

Правила заимствованы из бота (`MaxBotService.ShowDayAsync`) и семестрового экспорта (`ScheduleExportService.BuildSemesterCell`) — единый источник:

1. **Воскресенье** → `isSunday = true`; `entries`, `inserts`, `practices` пусты.
2. **Нерабочий день** (дата попадает в `DateFrom…DateTo`) → `isNonWorking = true`, `nonWorkingTitle = Title`; `entries`, `inserts`, `practices` пусты.
3. **Практика** (для группы — `GroupId`, для преподавателя — `TeacherId`) → `practices[]` заполнен; `entries` и `inserts` пусты.
4. **Обычный день**:
   - `inserts` — только активные (`IsActive`), по дню недели, для группы — `Course == null || Course == Course группы`; если группа не задана — все активные;
   - `entries` — по фильтрам `groupId`/`teacherId`/`room`, неделя должна входить в `Weeks`; время подменяется из справочника звонков по `NumberPair`; пары с примечанием «сам.р.» присутствуют с бейджем;
   - `changeTags` — из `ScheduleHistory` (существующий механизм).

`PracticeKind` в ответах — строки `Up`/`Pp` (enum); подписи «УП»/«ПП» — на клиенте.

## 3. API-контракты

Все ответы — `Result<T>` (200). Невалидные параметры → `400` с русским сообщением. Доступ — как у текущего `GET /api/schedule` (`AllowAnonymous`).

### 3.1. День

```
GET /api/schedule?view=day&date=YYYY-MM-DD&groupId=&teacherId=&room=
```

- `date` по умолчанию — сегодня (UTC); невалидный формат → `400` «Неверный формат даты.».
- `week` и `dayOfWeek` вычисляются по `date` (`StudyWeek.WeekOf`).
- Дата вне семестра: `week` клампится в `1…TotalWeeks`, `entries`/`inserts` пусты; нерабочий день на такой дате всё равно возвращается (`isNonWorking` + `nonWorkingTitle`).

```json
{
  "date": "2026-09-21T00:00:00Z",
  "week": 4,
  "dayOfWeek": 1,
  "isSunday": false,
  "isNonWorking": false,
  "nonWorkingTitle": null,
  "practices": [],
  "inserts": [],
  "entries": []
}
```

`practices` — `PracticeResponse[]`; `inserts` — `ScheduleInsertResponse[]`; `entries` — `ScheduleResponse[]` (существующий DTO с `changeTags`).

### 3.2. Неделя

```
GET /api/schedule?view=week&week=4&date=&groupId=&teacherId=&room=
```

- `week` — приоритетный параметр; если не задан, вычисляется из `date`; иначе — текущая неделя. Значение клампится в `1…TotalWeeks`.
- Ответ: `{ week, weekStart, days[6] }` — дни Пн–Сб с датами; каждый день — структура из 3.1 (с теми же правилами слоёв).

### 3.3. Календарь месяца

```
GET /api/schedule?view=calendar&month=YYYY-MM&groupId=&teacherId=&room=
```

- `month` по умолчанию — текущий; невалидный формат → `400` «Неверный формат месяца.».

```json
{
  "year": 2026,
  "month": 9,
  "days": [
    {
      "date": "2026-09-01T00:00:00Z",
      "dayOfWeek": 2,
      "isSunday": false,
      "isNonWorking": false,
      "nonWorkingTitle": null,
      "practiceKinds": ["Up"],
      "isOutOfSemester": false,
      "pairCount": 4
    }
  ]
}
```

- `days` — все даты месяца; `pairCount` — число пар по правилам 2.2 (0 в воскресенье/нерабочий/практику);
- `practiceKinds` — виды практик, покрывающих дату (для группы/преподавателя);
- `isOutOfSemester` — дата вне `[SemesterStart; SemesterStart + TotalWeeks·7 − 1]`.
- Сетка (ведущие/замыкающие дни) достраивается на клиенте.

### 3.4. Семестр

```
GET /api/schedule?view=semester&groupId=|teacherId=
```

- Ровно один из `groupId`/`teacherId`, иначе `400` «Укажите одну группу или одного преподавателя.».
- Ответ: `{ totalWeeks, weeks: [{ week, weekStart, days[6] }] }`; каждая ячейка — структура из 3.1.
- Один запрос на вид без N+1; для группы ≤ ~800 записей.

### 3.5. Обратная совместимость

`view=calendar` без `month` больше не возвращает «шаблон недели» — это месячный вид текущего месяца. Обновляются: веб-клиент `CollegeLMS.Next/api/schedule.ts`, интеграционный тест `ScheduleControllerTests` (calendar-тест), Postman-коллекция. Неизвестное значение `view` — прежнее поведение (paged-список).

## 4. Экспорт дня и недели (UC-SCH-09)

```
GET /api/schedule/export?scope=day|week&date=&week=&groupId=&teacherId=&room=&format=pdf|xlsx&layout=grid|daycards
```

- `scope=day`: `date` по умолчанию — сегодня; `scope=week`: `week` по умолчанию — текущая.
- Состав — из тех же слоёв (2.2): время звонков, бейджи, вставки, практики, нерабочие дни.
- Ошибки: нерабочий день → `400` «Нерабочий день: {Title}»; нет данных (воскресенье, пустой день/неделя) → `404` «Нет данных для экспорта».
- Имена файлов (FILE-3): `Расписание_день_dd.MM.yyyy_HH-mm-ss.xlsx|pdf`, `Расписание_неделя_dd.MM.yyyy_HH-mm-ss.xlsx|pdf`.
- Параметр `period` из экспорта удаляется (замена — `scope` + `date`/`week`); вызовы обновляются.
- `scope=semester` не меняется.
- Веб: экспорт-меню подставляет scope/date/week текущего режима; в режиме «Календарь» экспорт недоступен.

## 5. Веб `/schedule`

### 5.1. Режимы и состояние

Переключатель «День / Неделя / Календарь / Семестр». Состояние в URL:

- `?view=day&date=2026-09-21`
- `?view=week&week=4`
- `?view=calendar&month=2026-09`
- `?view=semester`

Старые deep-link'и из раздела «Изменения» (`?week=5&day=3` без `view`) конвертируются в `view=day` с вычисленной датой.

### 5.2. Поведение режимов

| Режим | Содержание |
|-------|------------|
| **День** | Навигация по дате (‹ / пикер / › / «Сегодня»), день недели и номер недели. Карточки пар (`ScheduleTable`: время, преподаватель, аудитория, группа, бейджи, «Сейчас идёт»); блок «Вставки» отдельной строкой без номера пары; карточка практики (УП/ПП, группа, преподаватель, организация, примечание); «Нерабочий день: {название}»; воскресенье — «Выходной». Диспетчерские действия: «Добавить», редактирование, удаление — сохраняются |
| **Неделя** | Пн–Сб с датами и номером недели. ≥lg — 6 колонок; <lg — вертикальные дни. В колонке: вставки, пары с бейджами, практика на весь день, «Не работает: {название}», пусто — «Нет пар» |
| **Календарь** | Сетка месяца 7×N: число, количество пар, маркеры — праздник (подсказка с названием), практика УП/ПП. Воскресенья и даты вне семестра приглушены. Клик → «День» на эту дату. Навигация ‹ месяц › |
| **Семестр** | Матрица «недели 1…TotalWeeks × Пн–Сб»: sticky-колонка недель, горизонтальный скролл на мобильных. В ячейке — компактные пары (номер, предмет, аудитория, бейджи), вставки, практика, «Не работает». Клик по ячейке → «День». Без выбранной группы/преподавателя — приглашение выбрать (запрос не выполняется) |

### 5.3. Общее

- **Дефолт пользователя:** при загрузке — `GET /api/schedule/context`; студент → своя группа, преподаватель → он сам; «Сбросить» возвращает к дефолту; для остальных ролей — без фильтра.
- **Семестр:** `semesterStart`/`totalWeeks` — из `GET /api/schedule/meta`; хардкод `2026-09-01` и `52` из компонентов удаляется.
- **UI-состояния:** UI-1 скелетон/спиннер; UI-2 «Нет данных»; UI-3 ошибка + кнопка «Повторить»; UI-4 тосты после мутаций.
- **Адаптивность:** проверка 393px (Xiaomi Mi 9 SE), 1366×768 (Toshiba A665), 1920+; touch-target ≥ 44×44.
- **Экспорт-меню:** PDF/XLSX, «Сетка»/«По дням»; scope по режиму (5.2/4).

### 5.4. Компоненты и клиент

Новые: `components/ScheduleViewSwitcher.tsx`, `DayNavigation.tsx`, `ScheduleDayView.tsx`, `ScheduleWeekView.tsx`, `ScheduleMonthCalendar.tsx`, `ScheduleSemesterMatrix.tsx`, `ScheduleLayers.tsx` (блоки «Вставки»/«Практика»/«Нерабочий»).

Удаляются: `DayTabs.tsx`, `SemesterView.tsx`.

Изменяются: `app/(authenticated)/schedule/page.tsx`, `api/schedule.ts` (`fetchScheduleView` — день/неделя/семестр/календарь; `exportSchedule` — scope/date/week; удаление `fetchScheduleCalendar`), `types/schedule.ts` (view-типы), `ScheduleTable.tsx` (переиспользование в «Дне»).

## 6. Мини-приложение Max

- Данные расписания — из `view=day` и `view=week` (замена текущих вызовов `fetchSchedule`/`fetchDaySchedule` в `ScheduleView.tsx`).
- **День** (`DayFeed`): блок «Вставки», карточка практики (заменяет пары), «Нерабочий день: {название}», воскресенье — «Выходной».
- **Неделя** (`WeekFeed`): маркеры практики/нерабочего/вставок по дням; пустые дни — «Нет пар».
- Deep-link'и (`today`/`day`/`week`/`schedule`) сохраняются; `view=calendar` в мини-приложении не используется.
- Новых режимов и настроек нет.
