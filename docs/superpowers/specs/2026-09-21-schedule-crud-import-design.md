# Дизайн-спецификация: расписание — ручной CRUD и импорт (UC-SCH-06/07/08)

**Дата:** 2026-09-21
**Статус:** утверждена пользователем (секции в чате, 2026-09-21)
**Цель:** закрыть оставшиеся требования эталонного ТЗ по ручному редактированию расписания и импорту XLSX: время пар из справочника звонков, валидация недель и пересечений по неделям, корректный разбор шаблона с полным списком ошибок, строгий `confirm` с отчётом.

**Источник требований:** `docs/spec/task-schedule-management.md` — UC-SCH-06, UC-SCH-07, UC-SCH-08.

### 1.2. Не входит

- **CFG-1** — семестр остаётся на `StudyWeek` (старт 2026-09-01, 16 недель); вынос в конфиг — отдельная итерация.
- **Избранное** (UC-SCH-39/42), бот/мини-апп (кроме отображения ошибок/отчёта на веб-странице `/schedule`).
- Нормализация в виде таблицы-справочника в БД (выбран словарь правил в коде).
- Парковка прошлой итерации: `CorrectionPositionEditor.tsx` (стухшее `вм.X` при ручной правке старого номера) — отдельным follow-up.

### 1.3. Совместимость

- `CreateScheduleRequest`/`UpdateScheduleRequest` теряют поля `StartTime`/`EndTime` (ломающее изменение контракта для веба; другие клиенты этих endpoint не используют). Ответы всегда содержат время из звонков.
- `PreviewAsync` с ошибками меняет статус с `400` на `200` (ошибки — часть тела); `400` остаётся только для FILE-1 (не `.xlsx`, >10 МБ, нечитаемый файл).
- `ConfirmResult` дополняется `Errors`, `Groups`, `Teachers`; `Schedule` сохраняется для совместимости.

## 2. Время пар — единый источник (UC-SCH-06, UC-SCH-07)

- `ScheduleService.CreateAsync/UpdateAsync`: сервер игнорирует время из запроса; берёт `IBellScheduleService.GetTimeMapAsync` по `NumberPair`; при отсутствии пары в справочнике — fallback `ScheduleImportService.GetPairTime(day, pair)` (существующие дефолтные слоты; у корректировок/дашборда поведение не меняется).
- Импорт (`ParseScheduleMatrix`, `ConfirmAsync`): время из карты звонков, fallback — тот же `GetPairTime`.
- Ответы `Create/Update/GetById` — с временем из звонков (подмена как в `GetAllAsync`).
- Фронт `ScheduleEntryDialog`: поля `type="time"` удаляются; отображается вычисленное время «08:30–09:50 · из справочника звонков» (данные `GET /api/bells`), пересчёт при смене номера пары.
- Валидаторы `StartTime < EndTime` удаляются (время формирует сервер из валидированного справочника).

## 3. Недели и пересечения (UC-SCH-06)

- **Недели:** дедупликация и сортировка; допустимый диапазон `1…StudyWeek.TotalWeeks`; иначе `400` «Неделя должна быть в диапазоне 1–16.» (текст зависит от `TotalWeeks`). Проверка в FluentValidation (`RuleForEach(x => x.Weeks).InclusiveBetween(1, TotalWeeks)`) и в сервисе (страховка).
- **Пересечения:** кандидаты выбираются по день+номер пары+пересечение времени+совпадение группы/преподавателя/аудитории, затем в памяти проверяется пересечение недель (`Weeks.Intersect(...).Any()`); `409` только при реальном пересечении недель; сообщения прежние («У группы уже есть занятие в эту пару» и т.д.).
- `UpdateAsync` исключает свою запись (`excludeId`).
- **Фронт:** `ScheduleEntryDialog` получает `totalWeeks` из `fetchScheduleMeta()` (страница уже загружает meta); ввод недель валидируется по `totalWeeks` (диапазон, плейсхолдер, ошибка под полем).

## 4. Импорт: парсер и превью (UC-SCH-07)

### 4.1. Разбор

- **Пары 1–8:** `pairRows` принимает номера 1–8; номер вне диапазона — ошибка данных строки «номер пары N вне диапазона 1–8» (мёртвая ветка `>7` удаляется).
- **Недели:** `w < 1 || w > StudyWeek.TotalWeeks` → ошибка «неделя N вне семестра (1…16)»; сообщение содержит актуальный `TotalWeeks`.
- **Формат ошибок:** `Message` формируется на сервере целиком: «Лист {имя}, строка N, столбец M: {текст}»; `Level` = `"structure"` (лист/шапка/дни/формат файла) или `"data"` (ячейки); поля `Sheet`, `Row`, `Column` заполняются структурно. Фронт выводит `Message` как есть (двойной префикс удаляется).
- **Все ошибки:** убираются ранние `return` при отсутствии групп/дней (после ошибки структуры парсинг продолжается, если это возможно); разбор файла оборачивается в try/catch → структурная ошибка «Не удалось прочитать лист» вместо 500; неизвестный текст дня в столбце A при наличии номера пары в B → структурная ошибка «неизвестный день недели "{текст}"».
- **Нормализация (словарь в коде):** существующий словарь синонимов предметов расширяется до именованного `SubjectSynonyms` (+ текущие regex-правила сохраняются); `NormalizeTeacherName` дополняется: trim, схлопывание пробелов, нормализация точек в инициалах («И. И.» → «И.И.»); сравнение преподавателей при confirm — по канонизированному ключу.

### 4.2. Превью

- `ParseScheduleMatrix` возвращает `entries` и `errors` одновременно (даже при наличии ошибок позиции, которые удалось разобрать, попадают в `prefix`-результат).
- `PreviewAsync`: `IsSuccess = true`, `Preview = { TotalEntries = entries.Count, Entries = entries, Errors = errors }`; `IsSuccess = false` — только нечитаемый файл/не XLSX.
- Контроллер: `400` для `IsSuccess = false` (FILE-1), иначе `200` с записями и ошибками.

## 5. Подтверждение импорта (UC-SCH-08)

- **Валидация `confirm`:** каждая позиция проверяется повторно (пары 1–8, недели в семестре, день недели корректен, `GroupName`/`Subject`/`Room` непусты); при ошибках — `ConfirmResult { IsSuccess = false, Errors = [...] }`, контроллер `400`; пустой список позиций — `400` «Нет позиций для импорта».
- **Полная замена** в одной транзакции (существующее поведение) — без изменений.
- **Курс группы:** из числовой части имени берётся первая цифра (ИС-21 → 2, 1-11 → 1, без цифр → 1), кламп 1–4.
- **Преподаватели:** поиск существующего `User` (роль Teacher) по канонизированному ФИО; если найден и `Teacher`-профиля нет — профиль создаётся для существующего пользователя; если есть — используется; иначе создаются `User`+`Teacher` (как сейчас). Дубли `User` по одному ФИО не создаются.
- **Отчёт:** `ConfirmResult { Imported, Groups, Teachers, Schedule, Errors }`; `Groups`/`Teachers` — количество **созданных** записей.
- **Фронт `ScheduleImportDialog`:** кнопка «Загрузить» (вместо «Импортировать»), блокируется при непустом списке ошибок; ошибки выводятся из тела `200`/`400` (через `err.response.data`), без дублирующего префикса; после успеха — отчёт «Пары: N · Группы: M · Преподаватели: K» и тост (UI-4).
