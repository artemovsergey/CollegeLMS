# Roadmap: мини-приложение MAX

Статус: **документация, код не пишем**. Настоящая спецификация определяет, как превратить бота Max в CollegeLMS в полноценное мини-приложение платформы MAX.

## Цель

Бот Max уже умеет: показывать расписание (сегодня/неделя), присылать уведомления об изменениях, ежедневный дайджест по будням, стилизованные Markdown-сообщения с маркерами изменений. Следующий шаг — уровень мини-приложения: интерактивный UI внутри MAX вместо текстовых сообщений.

## Требования платформы MAX (организационные)

До публикации мини-приложения необходимо пройти модерацию платформы:

- **Юридическое лицо**: регистрация разработчика как юрлицо, ИП или самозанятый — в зависимости от лимитов и доступности для СТВКК (госучреждение, колледж).
- **Верификация**: подтверждение учётной записи разработчика (документы, ИНН, реквизиты).
- **Модерация приложения**: заявка на публикацию с описанием, иконками, ссылкой на политику конфиденциальности; проверка безопасности и соответствия правилам платформы.
- **Песочница**: перед публикацией тестирование в режиме разработки на ограниченной аудитории.

## Технологический стек

| Компонент | Технология |
|-----------|------------|
| UI | `@maxhub/max-ui` на React |
| Мост в мессенджер | **MAX Bridge** (`window.Mx`) — получение контекста пользователя, вызов функций мини-приложения |
| Backend | Существующий CollegeLMS API (JWT, те же эндпоинты расписания/уведомлений) |
| Бот | CollegeLMS.MaxBot (Telegram-шлюз MAX) |

MAX Bridge даёт: авторизацию по контексту чата, `open_app` для перехода из сообщения в приложение, отправку сообщений назад в чат, доступ к профилю пользователя внутри закрытого чата.

## Кнопка `open_app` в сообщениях бота

Чтобы из текстового уведомления пользователь одним тапом попадал в интерактивное расписание:

- В `MaxButton` (`CollegeLMS.MaxBot/Models/Max/MaxButton.cs`) уже есть `Type`, `Text`, `Payload`, `Url`.
- Добавить тип кнопки `open_app`: `Type = "open_app"`, `Payload = { appId, route }` — открывает мини-приложение на нужном экране (например, «Расписание на завтра» → экран дня, «Изменение в расписании» → экран пары с деталями коррекции).
- Кнопку добавлять в `SendInlineKeyboardAsync` к уведомлениям `ChangeNotifier` и дайджесту `ScheduleNotifier`.
- Доступно только части аудитории, пока приложение не опубликовано — гард: выводить кнопку при флаге «мини-приложение доступно», иначе обходиться текстом.

## Этапы

### Этап 0: Готово (текущий бот)
- Стилизация сообщений, маркеры изменений, нумерация пар, фильтры уведомлений — реализованы.

### Этап 1: Инфраструктура
- [ ] Регистрация разработчика (юрлицо/ИП/самозанятый), верификация.
- [ ] Создание записи мини-приложения в кабинете MAX, получение `appId` и ключей.
- [ ] Домен и публичный HTTPS для мини-приложения (VPS уже есть).
- [ ] Знакомство с документацией MAX Bridge; прототип «hello world» на `@maxhub/max-ui`.

### Этап 2: Макет приложения
- [ ] Авторизация через контекст MAX Bridge + JWT CollegeLMS.
- [ ] Экраны: «Расписание (день/неделя)», «Изменения», «Мой профиль».
- [ ] Переиспользование API CollegeLMS без изменений: `/api/schedule`, `/api/dispatcher/dashboard` не нужен, `/api/schedule/history`.
- [ ] `open_app` из бота: уведомления и дайджест ведут на конкретные экраны.

### Этап 3: Публикация
- [ ] Заявка на модерацию (описание, иконки, политика конфиденциальности).
- [ ] Песочница: тестирование ограниченным кругом преподавателей/студентов.
- [ ] Публикация; бот подключает `open_app` для всех подписчиков.

## Риски и митигации

| Риск | Митигация |
|------|-----------|
| Модерация платформы затягивается | Начать регистрацию заранее; бот остаётся рабочим fallback |
| Требование юрлица/ИП у колледжа | Уточнить условия для образовательных учреждений; при необходимости опубликовать от имени организации |
| Отличия MAX Bridge от Telegram-кнопок | Прототип Этапа 1 до всех интеграций; сервис кнопок абстрагирован от `MaxApiClient` |
