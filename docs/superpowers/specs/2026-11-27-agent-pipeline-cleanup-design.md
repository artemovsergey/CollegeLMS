# Очистка агентского пайплайна (короткий дизайн)

Дата: 2026-11-27. Ветка: `refactor/agent-pipeline-cleanup`.

## Намерение

Применить уроки видео про устаревшие практики к агентскому пайплайну CollegeLMS:
уменьшить число обязательных инструментов и добавить независимое ревью в чистом
контексте. Без новых агентов, скиллов и оркестраторов.

## Цели

- Независимое ревью результата перед merge: один субагент в новой сессии, без
  доступа к контексту разработки и без права менять файлы.
- Обязательный минимум скиллов на роль; остальные доступны по необходимости.
- Корневой `AGENTS.md` короткий: детали живут в существующих скиллах.

## Не-цели

- Не менять код продукта, `.github/workflows`, compose и переменные окружения.
- Не менять роли, модели субагентов и порядок завершения работы (коммит → merge → push).
- Не добавлять новый «скилл пайплайна» или агента-оркестратора.

## Ограничения

- Ветка создана до правок. В рабочем дереве есть чужие неотслеживаемые файлы — не трогать.
- Проверки остаются на границах фаз; полный прогон тестов — в CI.

## Подходы

1. **Точечная чистка (выбран).** Меняем три существующих документа: `feature-workflow`
   (фаза 6 и таблица гейтов), `collegelms-roles` (минимум скиллов), `AGENTS.md`
   (ссылки вместо дублей). Новых компонентов нет.
2. Общий мета-скилл «контракт пайплайна» — отклонён: добавляет ещё один компонент,
   который надо синхронизировать, и повторяет уже существующие инструкции.
3. Свести пайплайн к одному агенту без ролей — отклонён: теряются границы файлов,
   модели и гейты, которые уже работают.

## Решённое

### Ревью в чистом контексте

- В [`feature-workflow`](../../../.opencode/skills/feature-workflow/SKILL.md) фаза 6
  получает подшаг после зелёного CI и до merge: один reviewer-субагент в новой
  сессии. Ему передаются только `"git diff master...HEAD"`, спецификация и
  чек-лист; он не видит историю переписки разработки.
- Проверяет: соответствие спецификации, качество тестов, соблюдение конвенций `AGENTS.md`,
  секреты в diff, риск миграций и деплоя. Отчёт — по тяжести (blocker/major/minor),
  без правки файлов и без git-операций.
- `blocker`/`major` → архитектор исправляет и повторяет ревью. В таблице гейтов
  добавляется строка G6. Скилл `requesting-code-review` остаётся доступным как
  источник чек-листа.

### Минимум скиллов

- В [`collegelms-roles`](../../../.opencode/skills/collegelms-roles/SKILL.md)
  обязательный список сокращается: Backend — `dotnet-entity`, `dotnet-endpoint`,
  `fluent-validation`, `swagger-docs`; Frontend — `design-system`, `nextjs-page`
  (плюс `modern-web-guidance` по уже существующему правилу `AGENTS.md`); Tester —
  `dotnet-test`, `test-driven-development`, `playwright`; DevOps —
  `docker-compose-dev`, `vps-deploy`, `cicd-pipeline`. Остатки переносятся в
  отдельный пункт «по необходимости» без удаления самих скиллов.
- В фазе 3 `feature-workflow` убирается `impeccable` и отдельный шаг polish/audit:
  дизайн-гейты уже есть в `quality.yml`. Остаются `design-system`, `nextjs-page`,
  `modern-web-guidance`.

### Короткий AGENTS.md

- Разделы «Прод и стенд» и «Агенты и модели», включая DSH, заменяются ссылками на
  `vps-bb-status`, `dsh-environment` и `.bb/skills/collegelms-dev`. Там уже есть
  путь прод-каталога, порог 3 ГБ, `journalctl`, настройки MCP и адрес Playwright.
- Остаются: пути, секреты, ветки и порядок завершения, таблица команд, раздел
  Frontend и конвенции .NET / EF Core.

## Оставлено реализации

- Точные формулировки и порядок правок; добавление одного подшага и одной строки
  в таблицу гейтов; проверка, что вынесенные факты действительно есть в скиллах.
- Верификация: `git diff --check` в обоих репозиториях, для CollegeLMS —
  `dotnet build CollegeLMS.slnx` и `npm run check:design-system` не требуются
  (изменения только в markdown), но при наличии времени запускаются по правилам проекта.
- Коммит в рабочую ветку; merge/push — по общим правилам проекта.
