# Дизайн: экзамены в корректировках расписания

Дата: 2026-11-19

## 1. Зачем

Сейчас корректировки работают только с парами: каждая позиция привязана
к номеру 1–7 и времени из звонков. Экзамен — не пара: в выгружаемом диспетчером
XLSX он выглядит отдельной строкой, где в колонке «Вводится в расписание →
Предмет» стоит слово **«ЭКЗАМЕН»**, а номер пары, преподаватель и примечание
пусты. Такого механизма в системе нет: `LessonType.Exam` существует, но в флоу
корректировок экзамен не создаётся и не отображается.

Цель — добавить в пакет корректировок третью операцию «Экзамен» и тем самым
закрыть разрыв между тем, что диспетчер видит в готовом XLSX, и тем, что умеет
система.

## 2. Цели / не-цели / антицели

**Цели**
- Создавать и редактировать позицию «Экзамен» в пакете корректировок.
- После применения экзамен попадает **и в расписание группы** (день/неделя, бот,
  мини-приложение), **и в журнал изменений, уведомление Max и XLSX**.
- XLSX-строка экзамена совпадает с образцом: группа, «ЭКЗАМЕН» в «Вводится»,
  пустые «Снимается», преподаватель, № и примечание.
- Сохранить обратимость XLSX: импорт файла с такой строкой создаёт ту же позицию.

**Не-цели**
- Отдельная сущность/страница «Экзамены» вне пакетов корректировок.
- Привязка экзамена к номеру пары, времени или преподавателю.
- Изменение механики «Вставок» и сам.р.

**Антицели**
- Сломать существующие XLSX, где «ЭКЗАМЕН» уже встречается в предметной колонке.
- Нарушить конвенцию «журнал показывает только Добавлено/Снято».

## 3. Ограничения

- `Result<T>`, без try-catch в контроллерах и сервисах, FluentValidation с
  сообщениями на русском, `AsNoTracking()` на чтении, ручные мапперы.
- Перечисления хранятся строками (`HasConversion<string>()`), поэтому новое
  значение enum **не требует миграции**.
- `schedule_entries.NumberPair` — `int NOT NULL`, но CHECK-ограничения на
  диапазон в БД нет (`ScheduleEntryConfiguration.cs:17`), 0 допустим.
- Экспорт уже обрабатывает `NumberPair == 0` как пустую ячейку
  (`ScheduleCorrectionService.cs:124-129`) — шаблон XLSX менять не нужно.
- Swagger и Postman-коллекция обязательны для каждого endpoint.

## 4. Рассмотренные подходы

| Подход | Суть | Оценка |
|---|---|---|
| **1. Третья операция в пакете (выбран)** | «Экзамен» рядом с «Добавить»/«Снять», позиция с парой 0, проходит существующий конвейер apply → журнал → Max → XLSX → откат | Совпадает с образцом 1:1, минимум новых слоёв, нет миграции |
| 2. Отдельная сущность «Экзамены» + CRUD | Своя таблица, страница, экспорт | Экзамен в образце живёт внутри корректировки; дублирует журнал/уведомления/экспорт, заметно больше работы |
| 3. Переиспользовать «Вставки» | Отдельная строка дня без пары | Вставки не привязаны к группе и не попадают в XLSX — пришлось бы допиливать оба места |

Выбран подход 1. Пользователь подтвердил: экзамен должен отображаться **и в
расписании, и в XLSX/журнале**.

## 5. Решение (как делаем)

### 5.1. Модель

- Добавить `Exam` в `ScheduleChangeType` (`Add, Remove, Replace, Move, Exam`).
  Хранится строкой — миграция не нужна.
- Позиция «Экзамен» — это `CorrectionPosition` с:
  - `ChangeType = Exam`, `NumberPair = 0`, `Subject = "ЭКЗАМЕН"`;
  - `TeacherId`/`TeacherName`/`Note` = null, `Room` не используется;
  - `GroupId`/`GroupName` обязательны, `Week`/`DayOfWeek` — из даты пакета.
- Валидация: для `Exam` пара **должна** быть 0; для остальных типов 0 запрещён.
  Изменить неявные проверки в `CorrectionBatchService` (~стр. 816) и
  `CorrectionApplyEngine.ValidateBatchAsync` (~стр. 279).

### 5.2. Применение и откат

- Apply создаёт `ScheduleEntry`: `LessonType = Exam`, `NumberPair = 0`,
  `Subject = "ЭКЗАМЕН"`, `GroupId`, `Weeks = [week]`, `DayOfWeek`, без преподавателя.
- Запись `ScheduleHistory` с `ChangeType = Exam`. Для отображения бейджа
  `changeTagKind(Exam)` → `Add`: в журнале остаются два исхода
  («Добавлено»/«Снято»), а название «ЭКЗАМЕН» видно в заголовке записи.
- Откат (`DELETE /api/schedule/history/{id}`) для `Exam` работает как для `Add`:
  убрать неделю из созданной записи, удалить запись, если недель не осталось,
  удалить саму запись журнала.
- Уведомление Max: строка «🟢 ЭКЗАМЕН» добавляется в дайджест группы; PNG и
  XLSX используют те же данные позиции.

### 5.3. XLSX

- Экспорт: `ToManualRow` отдаёт `AddedSubject = "ЭКЗАМЕН"`, `NumberPair = 0`;
  уже существующий код записывает пустую ячейку «№». Результат — как на образце.
- Импорт: строка с предметом «ЭКЗАМЕН» в «Вводится» распознаётся как `Exam`
  (номер пары игнорируется и нормализуется в 0) — это решение сделано для
  совместимости со старыми файлами диспетчера.

### 5.4. Отображение и UI

- `ScheduleViewService`: записи с `NumberPair == 0` и `LessonType == Exam`
  выносить из `Entries` в отдельный массив `Exams` ответа дня/недели — по образцу
  `Inserts`. Это даёт отдельную карточку дня без номера пары и времени, не ломая
  существующую группировку по 1–7. Frontend:
  карточка «Экзамен» с бейджем, цвет из токена `--lesson-exam`.
- `CorrectionPositionDialog`: третья операция «Экзамен» в переключателе;
  при ней скрываются шаги «Пара», «Преподаватель», «Предмет», «Примечание»,
  остаётся только выбор группы. Предпросмотр строки: «Группа — ЭКЗАМЕН».
- `CorrectionPositionEditor`: фильтр типа и бейдж дополняются «Экзамен»;
  `types/correction.ts` — `CorrectionChangeType` дополняется `"Exam"`,
  `changeTagKind("Exam") = "Add"`.
- В боте и мини-приложении экзамен показывается той же карточкой, что и в вебе.

### 5.5. Тесты и документация

- Unit: валидация (0 только для Exam), apply создаёт запись с `LessonType = Exam`,
  revert её убирает, `ToManualRow` даёт пустой «№», импорт строки «ЭКЗАМЕН».
- Integration: POST позиции Exam → apply → экспорт XLSX содержит строку как на
  образце → день расписания содержит `Exams`.
- Swagger-примеры, Postman-коллекция, ТЗ `docs/spec/task-dispatcher-corrections.md`
  (раздел 4.1/5.1) и `collegelms-schedule` — обновить описание операций.

## 6. Что остаётся исполнителю

Все вышеперечисленные пункты — это и есть объём реализации. Порядок: сначала
backend (enum, валидация, apply/откат, XLSX, view), тесты, затем frontend и бот,
затем документация. Отдельно оговорённого выбора больше нет; если в процессе
возникнет расхождение с образцом XLSX — ориентироваться на образец из фото
пользователя как на эталон формата.
