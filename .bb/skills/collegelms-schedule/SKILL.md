# CollegeLMS: домен расписания

## Источники требований

- `docs/spec/task-schedule-management.md` — эталонное ТЗ (приоритет выше кода).
- `docs/spec/task-schedule-reference-data.md` — звонки, нерабочие дни, вставки,
  практики, экспорт, журнал.
- `docs/spec/task-dispatcher-corrections.md` — флоу корректировок.
- `docs/spec/userstories.md` — пользовательские истории.

Если код расходится с ТЗ — это дефект, а не новое требование.

## Базовые понятия

| Термин | Правило |
|---|---|
| Пара | номер 1–8, время из справочника звонков |
| Неделя | учебная неделя семестра с 1; границы — `Semester:StartDate` и `Semester:TotalWeeks` |
| Семестр | единый источник — `GET /api/schedule/meta`; дублировать константу нельзя |
| Группа/преподаватель | пара может быть на подгруппу; склейка подгрупп — только при совпадении дня, номера, группы, предмета и набора недель |

## Корректировки

- Пакет — на одну дату; статусы `Draft` / `Applied`; применённый пакет повторно
  не применяется (`409`).
- Позиции: добавить, снять, заменить, перенести. Применение — в одной
  транзакции: либо все изменения, либо ни одного.
- `сам.р` — только пометка, пара в базу не встаёт и слот не занимает.
- `сам.р+` — пара добавляется и помечается как самостоятельная работа.
- `вм.X` — перенос: освобождается пара X того же преподавателя и предмета;
  допустим только для ввода.
- Снятие: неделя удаляется из пары; если недель не осталось — запись удаляется.
- Нерабочая дата: создание и применение корректировки → `400` с названием дня.
- Бейджи: «Добавлено», «Снято», «Сам.р.», замена — «старое => новое»,
  перенос — «пара X → Y». Видны в вебе, мини-приложении, боте и экспорте.

## Нерабочие и рабочие дни

- `NonWorkingDay`: `DateFrom ≤ DateTo`, одиночная дата — совпадают.
- На нерабочую дату пары не выводятся, но остаются в БД; бот показывает
  «🎉 Нерабочий день: {Title}», рассылка пропускается; экспорт дня → `400`.
- `WorkingDayOverride` делает выходной рабочим и может подставить расписание
  дня `SubstituteDayOfWeek` (1–5). Пересечение с нерабочим днём → `409`.

## Звонки

- До 8 пар, 07:00–21:00, по возрастанию, без пересечений; большая перемена —
  после пары N, в расписании отдельным событием не показывается.
- Профили звонков: базовый, по дням недели и по датам; резолв на дату —
  дата → подменяемый день → день недели → базовый.
- Время пар подменяется из справочника во всех слоях: расписание,
  корректировки, экспорт, бот, мини-приложение.

## Практики УП/ПП

- `Practice`: вид `Up`/`Pp`, период в пределах семестра, ≥1 преподаватель.
- Несколько УП одной группы с одинаковым периодом — подгруппы (разрешены);
  другое пересечение практик группы → `409`.
- День УП: `PracticeDay.PairNumbers` (1–8) синтезирует пары с
  `LessonType=Practice`, время из звонков, emerald-подсветка; обычные пары и
  вставки в этот день подавляются (перспектива группы).
- День ПП: карточка практики (amber), пар нет.
- Перспектива преподавателя: слой `practices[]` пуст; в день УП — обычные пары
  + пары УП, в день ПП практика не показывается; суббота попадает в неделю
  только при УП.

## Вставки

- Отдельная строка дня без номера пары; воскресенье запрещено; `Course` 1–4
  или пусто (все курсы); неактивные не отдаются.
- Сиды: «Разговор о важном» (Пн 08:30–09:00), «Классный час» (Чт 12:10–13:00).

## Журнал преподавателя

- Только проведённые занятия: от начала семестра до сегодня (UTC).
- Одна пара дня — отдельный элемент; бейджи корректировок в `changeTypes[]`.
- `Teacher` видит только себя; `Admin`/`Dispatcher` — по `teacherId`.

## Конвенции кода

- `Result<T>` во всех сервисах; try-catch в контроллерах и сервисах запрещён.
- FluentValidation, сообщения на русском; `AsNoTracking()` на чтении.
- GUID PK `ValueGeneratedNever()`, enum-ы строками, `HasMaxLength`, индексы в
  конфигурациях, CHECK в `Data/DbConstraints.cs`.
- Swagger и Postman-коллекция обязательны для каждого endpoint.
- Импорт XLSX ≤10 МБ; имена файлов с таймстемпом по `FILE-3`.
