# Дизайн-система CollegeLMS

Единственный нормативный документ. Описывает систему **в том виде, в каком она
реализована сейчас**. Значения в документе и в `CollegeLMS.Next/app/globals.css`
должны совпадать; расхождение — дефект.

Исторические документы дизайна не задают правил и не являются источником истины.

---

## 1. Идентичность

Колледж — государственное бюджетное профессиональное образовательное учреждение.
Тон: сдержанный, академический, открытый. Никакой «стартапной» яркости.

Знак — герб с тёмно-синей окантовкой щита, лазурным глобусом, зелёными лавровыми
ветвями, сиреневой лентой с именем и кремовым отражателем. Палитра интерфейса
настроена на лазурно-синий и зелёный из знака; ленты и крема в интерфейсе нет.

## 2. Где живут токены

Все токены объявлены в **`CollegeLMS.Next/app/globals.css`**:

| Блок | Назначение |
| --- | --- |
| `:root` | светлая тема |
| `.dark` | тёмная тема |
| `@theme inline` | маппинг `--color-*` для Tailwind v4 + `--font-sans` + анимации |
| `.accessibility-mode` | режим высокой контрастности (не токены, а принудительные переопределения — см. §6) |
| `.prose`, `@layer components` | типографские и контентные помощники |

Отдельных файлов `tokens/` нет. Это осознанно: единственный источник истины —
один файл, который редактируется вместе с `@theme inline`, поэтому рассинхрон
между токеном и его Tailwind-утилитой невозможен по построению.

### 3.3. Правило токена `primary`

`--primary` — алиас `--accent`. Он используется и как заливка (`bg-primary`),
и как цвет текста (`text-primary`). В тёмной теме это **светлая лазурь**,
поэтому `text-primary` допустим только на тёмных поверхностях
(`bg-card`, `bg-muted`, `bg-background`), а не на светлых плашках
(`bg-accent-light`, `bg-secondary`). Нарушение этого правила — самый частый
источник нечитаемого текста; проверяется гейтом §8.

### 3.4. Утилиты MAX-приложения

MAX — отдельное мини-приложение в мессенджере MAX, построенное на библиотеке
`@maxhub/max-ui`. Эта библиотека оформляется через **398 CSS-переменных**
(`--background-surface-*`, `--background-accent-*`, `--text-*`, `--stroke-*`,
`--icon-*`, `--states-*`, `--size-border-radius-*`, `--shadow-elevation-*` и др.),
поэтому единый стиль достигается **тем, а не форком**.

Правило: **цвета MAX задаются только через `var()` наших токенов из
`app/globals.css`.** Собственных цветовых литералов в `app/max/max.css` быть
не должно — это проверяет гейт `max-theme-tokens-only` (§8.1). `app/max` —
вложенный layout, поэтому токены из `:root` доступны внутри `.max-app`, а тема
приходит классом `.dark` на `<html>`; отдельного блока `.dark .max-app` нет и
не требуется.

Ключевой маппинг (полный список — в начале блока `.max-app` в `max.css`):

| Токен MaxUI | Наш токен |
| --- | --- |
| `--background-surface-ground` | `--background` |
| `--background-surface-card`, `--background-surface-primary` | `--card` |
| `--background-surface-secondary`, `-tertiary`, `--background-button-secondary` | `--muted` |
| `--background-accent-themed`, `--text-themed`, `--stroke-themed`, `--icon-themed`, `--accent-themed` | `--accent` |
| `--background-accent-contrast`, `--text-contrast` | `--accent-foreground` |
| `--background-accent-negative`, `--text-negative` | `--destructive` |
| `--background-accent-positive`, `--text-positive` | `--success` |
| `--background-accent-attention-primary` | `--warning` |
| `--background-accent-neutral`, `--text-primary`, `--icon-primary`, `--text-subhead` | `--fg` |
| `--text-secondary`, `--icon-secondary` | `--muted-foreground` |
| `--text-tertiary`, `--icon-tertiary` | `color-mix(in srgb, var(--muted-foreground) 72%, transparent)` |
| `--stroke-secondary` | `--border` |
| `--size-border-radius-*` (5 радиусов) | `--radius` |
| `--background-accent-neutral-themed`, `--text-neutral-themed`, `--icon-neutral-themed` | `--accent` |
| `--states-{background,text,icon}-{hovered,pressed,active}-neutral-themed` | `--accent-hover` |
| `--states-{background,text,icon}-disabled-neutral-themed` | `color-mix(in srgb, var(--accent) 40–55%, transparent)` |

**Обязательное правило: куда объявлять маппинг.** MaxUI надевает на
корневой элемент компонента собственный класс-харнесс темы —
`MaxUI_colorScheme_light__Woo` / `MaxUI_colorScheme_dark__jFq`, и **именно на
нём** объявлены все переменные MaxUI (не на `:root`, без `!important`). Этот
класс лежит **внутри** `.max-app`, поэтому объявления на самом `.max-app` не
видны: у вложенного элемента собственное объявление всегда выигрывает у
унаследованного, независимо от `!important` и специфичности предка.

Поэтому селектор маппинга в `app/max/max.css` — список из двух селекторов:

```css
.max-app,
.max-app [class*="MaxUI_colorScheme"] {
  /* …переопределения… */
}
```

Второй селектор даёт специфичность 0,2,0 против 0,1,0 у MaxUI и при этом не
привязан к хэшам в имени класса, поэтому переживает обновление библиотеки.
При добавлении новых переменных в маппинг менять ничего не нужно — правило уже
в блоке.

## 4. Типографика

Единственный шрифт — **Inter** (`@fontsource/inter`, веса 400/500/600/700),
подключается через `--font-sans`.

Шкала задаётся утилитами Tailwind, отдельной типографской шкалы токенов нет:

| Роль | Утилита | Размер |
| --- | --- | --- |
| Заголовок страницы | `text-3xl font-bold` | 30px |
| Заголовок секции | `text-2xl font-semibold` | 24px |
| Подзаголовок | `text-xl font-semibold` | 20px |
| Основной текст | `text-base` | 16px |
| Вторичный текст | `text-sm` | 14px |
| Подпись, метка | `text-xs` | 12px |

В `body` жёстко задан `font-size: 16px` и `font-feature-settings:
"cv02","cv03","cv04","cv11"` (Inter Character Set — визуально ровные знаки).

## 5. Пространство, форма, глубина

- Отступы: шаг 4px (`p-1`…`p-12` в единицах Tailwind).
- Базовый радиус: `--radius: 0.5rem` (8px). У примитивов — `rounded-md`
  (контролы) и `rounded-lg` (карточки и панели).
- Границы: `border` + `--border`; базовый слой включает `* { @apply border-border }`,
  поэтому цвет рамки наследуется от токена, а не задаётся вручную.
- Тени: `shadow-sm` для карточек, `shadow-lg` для оверлеев и модальных окон.
- `html { scrollbar-gutter: stable }` — полоса прокрутки резервируется всегда,
  чтобы не было горизонтального сдвига при блокировке скролла.
- То же правило действует внутри модальных окон (`dialog`, `[data-slot="dialog-content"]`)
  и у прокручиваемых списков (класс `.scroll-stable`): полоса резервируется всегда,
  поэтому появление скролла не сужает содержимое и интерфейс не дёргается.
  Проблема сквозная — без правила любой список, растущий при фокусе, сдвигает модалку.

## 6. Доступность

### 6.1. Базовые требования

- Интерактивные элементы — не меньше 44×44px (`min-h-11`, `size-11`).
- Видимый фокус: `focus-visible:ring-2 ring-ring` (или `outline`).
- Иконки — `lucide-react`, размеры `h-4` (в тексте), `h-5` (кнопки),
  `h-6` (заголовки). Иконка без подписи получает `aria-hidden`.
- Поля формы: видимая подпись, ошибка под полем, связь через `aria-describedby`,
  обязательность через `required` и `aria-required`.
- Состояние загрузки формы объявляется `role="status"` c `aria-live="polite"`.

### 6.2. Режим высокой контрастности

Переключатель `AccessibilityToggle` добавляет на `<html>` класс
`.accessibility-mode`. Это **не набор токенов**, а набор принудительных
переопределений:

| Правило | Эффект |
| --- | --- |
| `font-size: 18px; line-height: 1.6` | увеличенный текст |
| `img, video { display: none }` | скрытие декоративной графики |
| `* { animation: none !important; transition: none !important }` | отключение движения (кроме `.animate-spin`, `.animate-pulse`) |
| `a, button { text-decoration: underline; font-weight: 600 }` | подчёркивание ссылок и кнопок-как-ссылок |
| `.accessibility-mode` | переопределяет семантические токены в чёрно-белую схему |
| `.accessibility-mode a, button` | подчёркивание и полужирный |
| `.accessibility-mode .card` | усиленные рамки |
| `button:has([class*="lucide"])` | подложка вокруг иконочных кнопок |
| `.accessibility-mode img:not([data-brand-mark]), video:not([data-brand-mark])` | скрытие декоративной графики; знак колледжа исключён |

Оформление задаётся переопределением токенов, а не селекторами по подстрокам
классов: подстрочные селекторы сносили любую цветную поверхность, включая
статусные плашки, и разбирали семантику компонентов. Статус в этом режиме
передаётся текстом, а не цветом. Устройство режима — §10.4.

## 7. Поверхности

Публичный сайт, LMS, админка и MAX — **один продукт в четырёх оболочках**. Различаться
должны только оболочка (шапка, навигация) и плотность, но не язык.

**Обязательно общее для всех четырёх поверхностей:**

| Слой | Что общее |
| --- | --- |
| Токены | `:root` / `.dark` / `.accessibility-mode` из `app/globals.css`. MAX наследует их через `var()`, а не имеет своей палитры |
| Шрифт | Inter, веса 400/500/600/700 (§4). MAX переопределяет `--font`/`--family-base` на Inter |
| Типографика | Шкала §4. Заголовок страницы — `text-3xl font-bold`, раздел — `text-2xl font-semibold`, подзаголовок — `text-xl font-semibold`. Отклонения не по размеру, а по смыслу: подпись и метка — `text-sm`/`text-xs` |
| Форма и глубина | `--radius` 8px: `rounded-md` контролы, `rounded-lg` карточки. `shadow-sm` карточки, `shadow-lg` оверлеи (§5) |
| Отступы | Шаг 4px, один контейнер и один боковой отступ на поверхность |
| Состояния | `LoadingSpinner`, `ErrorBanner`, `EmptyState` — один набор на продукт, без копий в страницах |
| Интерактив | Видимый фокус одним рецептом, цель касания ≥44×44 (§6.1), никаких `transition-all` |
| Статусы | Только семантические токены: `--success`, `--warning`, `--destructive`, `--lesson-*`. Собственные оттенки Tailwind запрещены (§8.1) |
| Словарь | Один смысловой словарь терминов и подписей на продукт, включая бот |

**Допустимые различия оболочек:**

| Поверхность | Маршруты | Оболочка | Плотность |
| --- | --- | --- | --- |
| Публичный сайт | `/`, `/news`, `/specialties`, `/contacts`, `/partners`, `/login` и др. | `Header` (двухрядная шапка) + `Footer` | просторная, широкий контейнер |
| LMS | `/my`, `/teacher`, `/courses`, `/schedule` | `AuthenticatedShell` + однорядная шапка, навигация шторкой | средняя |
| Админка | `/admin/*` | та же шапка LMS, свой заголовок | средняя |
| MAX | `/max/*` | `MaxShell` с нижним таб-баром, `app/max/max.css` | плотная, колонка ≤560px — ограничение платформы |

Ширина контейнера, отступы и вид заголовка страницы — не «особенности поверхности»,
а часть оболочки: на каждой поверхности они должны быть одни, иначе страницы
перестают читаться как части одного продукта. Отличается только то, что задано
платформой: у MAX это нижняя навигация и предел ширины, у сайта — двухрядная
шапка.

## 8. Проверки

Две проверки запускаются командой `npm run check:design-system`.

### 8.1. `scripts/check-design-system.mjs` — правила исходников

| Правило | Что запрещает |
| --- | --- |
| `no-raw-hex` | литералы цвета в `.ts`/`.tsx` — только токены |
| `no-raw-palette` | встроенная палитра Tailwind (`bg-emerald-100`, `text-red-700`) — свой набор оттенков на каждую тему, мимо семантических токенов |
| `no-literal-bg-white` | `bg-white` как поверхность: в тёмной теме белый фон остаётся белым, а текст на нём токенный, то есть тёмный |
| `no-dead-token-function` | `hsl(var(--токен))` и прочие `цвет(var(…))`: токен уже готовый цвет, обёртка невалидна и декларация молча отбрасывается |
| `no-transition-all` | `transition-all` вместо перечисления свойств |
| `no-raw-select` | нативный `<select>` вместо примитива `Select` |
| `no-raw-table` | нативный `<table>` вместо примитива `Table` |
| `required-file` | наличие обязательных файлов |
| `forbidden-file` | отсутствие устаревших файлов |

Правила `no-raw-palette`, `no-literal-bg-white` и `no-dead-token-function` закрывают
не стиль, а согласованность: пока цвет можно задать помимо токенов, у каждой
поверхности появляется своя палитра и тёмная тема расходится с светлой.

`no-literal-bg-white` намеренно не проверяет `text-white` и `bg-white/10`: белый
текст поверх брендовой заливки (`bg-accent`, `bg-primary`) — законный паттерн, и
прозрачные белые подложки на ней читаются как блик, а не как поверхность.

У правил есть исключения, и это не смягчения, а зафиксированные решения:

| Исключение | Основание |
| --- | --- |
| `components/ui/table.tsx` — `no-raw-table` | сам примитив |
| `components/ui/native-select.tsx`, `components/FilterSelect.tsx` — `no-raw-select` | осознанные обходные примитивы на нативном `<select>`: нативная семантика и мобильные выпадающие списки |
| `components/Carousel.tsx` — `no-literal-bg-white` | слайды и их оверлеи лежат поверх фотографии: белый там часть композиции снимка, а не поверхность интерфейса |
| `components/CorrectionFilePreview.tsx` — `no-literal-bg-white` | предпросмотр листа XLSX: имитация белой бумаги задана явно (`dark:bg-card`) |

Baseline исходников **не пуст**: 62 известных нарушения, из них 58 — `no-raw-palette`

### 8.3. `e2e/design-system.spec.ts` — проверки в браузере

Четыре требования §6 и §7, которые нельзя проверить разбором исходников.
Файл создан потому, что §8.3 обещал эти проверки, а выполнял их ни один тест.

| Проверка | Что смотрит |
| --- | --- |
| `контраст текста` | WCAG 2.1 AA на реальном тексте: 4.5:1, для крупного 3:1. Обе темы |
| `ширина 320px` | отсутствие горизонтальной прокрутки — размер, который требует PRODUCT.md |
| `размер интерактивных элементов` | цель касания не меньше 44×44 |
| `доступность форм` | у полей есть видимая подпись и доступное имя |
| `видимый фокус` | первый элемент по Tab получает кольцо |

Контраст считается в браузере, а не разбором `getComputedStyle` в Node: Chromium
отдаёт результат `color-mix()` и любого `*-text/70` как `oklab(… / α)`, а не
`rgb()`. Проба через canvas молчала — присваивание `fillStyle = "oklab(…)"`
игнорируется, весь текст сравнивался сам с собой и давал ровно 1.00:1. Поэтому
oklab разбирается и переводится в sRGB прямо в тесте.

Допуск 0.15 к порогу — расхождение между браузером и точным разбором пар токенов
в §8.2: здесь цвет берётся из вычисленных стилей, там из файла токенов, и на
`oklab`-цветах путь округления даёт около 0.09. Реальные нарушения (2.16:1,
2.42:1, 2.7:1) допуском не маскируются.

Проверка 44×44 пропускает закрытые шторки и выпадающие меню: у них есть
размеры, но они скрыты — `visibility: hidden`, `inert` или обрезаны предком.
Последнее определяется тем, что реально лежит под точкой элемента: мобильная
шторка схлопывается через `grid-template-rows: 0fr`, и её дети сохраняют
размеры при нулевой видимой высоте.

Все 23 проверки проходят. Запускаются локально:
`npx playwright test e2e/design-system.spec.ts`.
В CI они не входят: контраст токенов и согласованность разметки уже закрыты
статическими гейтами, а браузерные проверки требуют поднятого сервера.

Проверки нашли четыре поломки, которые не видны в исходниках: название
колледжа на странице входа белым по белому (контраст 1:1), текст шапки в
тёмной теме 2.16:1, подписи статусов на собственной подложке 4.35:1 и
брендовый цвет на подложке `--accent/10` в тёмной теме 3.84:1. Последние две
привели к появлению семейства `--*-text`: один токен не может быть и
заливкой, и текстом на подложке от себя же.

## 10. Известные особенности и дефекты

Внешний вид считается согласованным. Ниже — только то, что важно знать при
работе с системой; правки требуют отдельного согласования, потому что меняют
поведение или облик.

### 10.1. Исправленные дефекты

1. Логотип на странице авторизации схлопывался до ~16px: `w-full` на `<img>`
   разрешался относительно контейнера, сжатого `align-items: center`. Исправлено
   фиксированной шириной (`w-64`) и `w-full` на контейнере.
2. Верхний ряд публичной шапки скрывался при скролле мгновенным `h-0`, из-за чего
   контент страницы прыгал на 48–56px. Теперь высота анимируется вместе с
   трансформацией (`transition-[height,transform] duration-300`), а скрытая строка
   помечается `aria-hidden`.
3. Мобильная панель навигации появлялась мгновенно. Теперь переход высоты сделан
   через grid-трюк `grid-rows-[0fr]` → `[1fr]` с `transition-[grid-template-rows,opacity]`
   и `aria-hidden` в закрытом состоянии.
4. Граница поля ввода не достигала порога 3:1: `:root --input` `#c9ceda` → `#7b8496`
   (3.76:1), `.dark --input` `#374151` → `#6b7280` (3.67:1).
5. Тёмная тема MAX переключалась по системной теме ОС. Теперь она следует
   переключателю темы приложения: селектор `.dark .max-app` вместо
   `@media (prefers-color-scheme: dark)`. Значения палитры не менялись.
6. `text-primary` и `text-accent` были нечитаемы в тёмной теме: белый текст на
   светло-голубой заливке `#568edd` давал 3.33:1. В `.dark` переменные
   `--primary-foreground` и `--accent-foreground` стали `#0f172a` — 5.36:1, AA.
7. `components/ui/dialog.tsx` собран на `React.forwardRef` — по образцу соседнего
   `alert-dialog.tsx`. Раньше это были обычные функции, и React писал
   предупреждение `Function components cannot be given refs` на `DialogOverlay`:
   Radix передаёт `ref` элементу, а функциональный компонент её принять не может.
   Теперь `DialogOverlay`, `DialogContent`, `DialogTitle` и `DialogDescription`
   пробрасывают `ref`, а `Dialog`, `DialogTrigger`, `DialogPortal`, `DialogClose`,
   `DialogHeader` и `DialogFooter` остались функциями — они не получают `ref` ни
   от Radix, ни от потребителей.

### 10.2. Правила, зафиксированные по итогам

8. `transition-all` запрещён гейтом `check-design-system`. Вместо него перечисляются
   конкретные свойства: `transition-[height,transform]`,
   `transition-[grid-template-rows,opacity]`, `transition-[max-height,opacity]`,
   `transition-[opacity,transform,visibility]`.
9. Изменение высоты элемента в потоке анимируется вместе с трансформацией, а не
   мгновенным переключением класса.
10. `components/ui/button.tsx` перечисляет анимируемые свойства
   (`transition-[color,background-color,border-color,box-shadow,opacity,text-underline-offset]`),
   а не использует `transition-all`. Если новый вариант кнопки начнёт менять
   другое свойство, анимации не будет, и гейт этого не заметит: он проверяет
   только запрет `transition-all`. Перечень правится вручную, сознательно.
11. Линия под последней строкой таблицы задаётся через `last:border-b!`
    (суффикс `!` — Tailwind v4). Без `!important` результат недетерминирован:
    примитив `TableBody` снимает границу у последней строки через
    `[&_tr:last-child]:border-0` — та же специфичность, что у `last:border-b`, и
    `twMerge` оставляет оба правила, так что решает порядок в собранном CSS.
    Снимать `!` нельзя: в сводке диспетчера линия под последней строкой была до
    миграции на примитив, и без `!` она пропадёт. В остальных 11 таблицах её до
    миграции не было — там поведение примитива совпадает с прежним видом, и `!`
    не применяется.

### 10.3. Осознанные решения, выглядящие как дефекты

12. Верхний ряд публичной шапки скрывается при скролле — это задумано
    (комментарий в коде «Row 1: Top bar — hides on scroll»), теперь без скачка
    макета (см. п. 2).
13. Скрытая строка шапки недоступна с клавиатуры, пока идёт скролл: она помечена
    `aria-hidden` и `pointer-events-none`.

### 10.4. Режим высокой контрастности: как он устроен

Класс `.accessibility-mode` ставится блокирующим скриптом в корневом
`app/layout.tsx`: он читает `localStorage["accessibility-mode"]` и добавляет
класс на `<html>` до первой отрисовки. Так режим не мигает при загрузке, а
`AccessibilityToggle` может переключать его в любой момент.

Оформление задаётся **переопределением семантических токенов**, а не селекторами
по подстрокам классов. Прежний вариант (`[class*="bg-"]`, `[class*="text-"]`,
`.bg-white`, `.text-white` с `!important`) сносил любую цветную поверхность,
включая статусные плашки, и разбирал семантику компонентов. Теперь в режиме
чёрно-белый, но компоненты сохраняют смысл: статус передаётся текстом, а не
цветом.

Декоративная графика скрывается, но знак колледжа — часть идентификации (§1),
поэтому исключён: элемент помечается `data-brand-mark`, и правило имеет вид
`.accessibility-mode img:not([data-brand-mark])`.

### 10.5. Цвета типов занятий: один набор вместо двух

Раньше одни и те же пять типов были раскрашены двумя несовпадающими наборами, и
одно и то же занятие выглядело по-разному в боте MAX и в сводке диспетчера.
Набор `--lesson-summary-*` удалён, остался единый `--lesson-*`:

| Тип | `:root` | Контраст на белом | `.dark` | Контраст на `#1f2937` |
| --- | --- | --- | --- | --- |
| Лекция | `#2563eb` | 5.17:1 | `#60a5fa` | 5.78:1 |
| Практика | `#047857` | 5.49:1 | `#34d399` | 7.64:1 |
| Лабораторная | `#a16207` | 4.92:1 | `#fbbf24` | 8.80:1 |
| Экзамен | `#be123c` | 6.28:1 | `#fb7185` | 5.46:1 |
| Нет занятия | `#475569` | 7.58:1 | `#94a3b8` | 5.73:1 |

Порог выбран 4.5:1, а не 3:1, потому что в MAX цвет типа используется как
**текст 12px** (`.max-schedule__type`), а в сводке — как заливка полосы, где
хватило бы 3:1. Держать 4.5:1 в обеих темах нужно, чтобы один и тот же токен
годился для обоих применений.

Значения не употреблены прямо из прежних наборов: единого значения на обе темы
не существует (4.5:1 на белом требует относительной яркости ≤ 0.18333, а на
`#1f2937` — ≥ 0.271836), поэтому в светлой теме цвета потемнённые, в тёмной —
светлые. В `.accessibility-mode` повторён светлый набор: режим всегда переводит
фон в белый.

В тёмной теме `--lesson-lab` = `#fbbf24` совпадает с `--warning` — лабораторная
работа и предупреждение принадлежат одному янтарному семейству.

### 10.6. Граница `--border`: доведена до 3:1

`--border` не достигал порога 1.4.11 (1.58:1 на белом, 1.42:1 на тёмной
карточке). Раньше это не проверялось, потому что контрастный гейт смотрел
только на токены веб-темы. Значения затемнены во всей системе сразу — иначе
miniapp оказался бы контрастнее веба, то есть единство было бы нарушено:

- светлая тема: `#c9ceda` → `#8a93a5`, 3.09:1;
- тёмная тема: `#374151` → `#6b7488`, 3.13:1 на `#1f2937`.

Два известных нарушения `stroke-secondary / background-surface-card` в MAX
закрылись автоматически: `--stroke-secondary` получает `var(--border)`.
`design-system-contrast.baseline.json` теперь пуст. Чтобы граница не
регрессировала, в гейт добавлены пары `--border / --background` и
`--border / --card` с порогом 3:1.

### 10.7. Исправлено: `text-foreground` больше не мёртвый

Раньше в `@theme inline` (`app/globals.css`) был объявлен `--color-fg: var(--fg)`,
но не `--color-foreground`. Поэтому класс `text-foreground`, который используют
примитивы `ui/table.tsx`, `ui/badge.tsx` и `ui/input.tsx` (а также `body` в
`app/layout.tsx` и ещё 13 файлов), **не генерировал CSS** — это был мёртвый класс.

Добавлен алиас `--color-foreground: var(--fg)`. Значение совпадает с `text-fg`,
который и так применён к `body` в `globals.css`, поэтому базовый цвет текста
страницы не изменился (`#111827` в светлой теме, `#f3f4f6` в тёмной) — изменилось
только то, что класс теперь действительно применяется.

Побочный эффект, ради которого и затевалась правка: переопределения вида
`[&_th]:text-muted-foreground` в таблицах из «страховки» превратились в
обязательные — без них подписи шапок стали бы основным цветом. Они и были
добавлены при миграции таблиц на примитив (`Design.md` §8.1), так что вид шапок
не изменился.

Заодно убран мёртвый токен `--foreground` из блока `.accessibility-mode`: на него
никто не ссылался, а режим высокой контрастности вместо этого переопределяет
`--fg: #000000` — то есть базовый цвет текста в режиме теперь действительно
чёрный, а не `#111827`.

### 10.8. Гейт проверял построчно и поэтому ловил ноль

Правила `no-raw-select` и `no-raw-table` применялись к отдельным строкам файла, а
регулярное выражение требовало символ сразу после имени тега: `/<select[\s>]/`.
JSX отформатирован так, что `<select` стоит последним символом строки, а дальше —
конец строки, то есть ни пробела, ни `>` там не бывает. Условие не выполнялось
никогда, и правило проходило по репозиторию, не находя ни одного нарушения, хотя
в проекте было 4 нативных `<select>` вне примитивов — включая форму входа.

Исправлено на `/<select(\s|>|$)/` и `/<table(\s|>|$)/`: конец строки допустим.
Заодно механизм исключений переведён с частного случая для `table.tsx` на
общий список `exempt` у правила — иначе каждое осознанное отступление пришлось бы
зашивать в основной цикл.

Тот же класс ошибки, но с другой стороны: `--update` записывал baseline и тут же
падал с кодом 1, поэтому обновить baseline в цепочке команд было невозможно.
Теперь `--update` завершается успехом и печатает, сколько нарушений записано.

### 10.9. `hsl(var(--токен))`: декларации, которые молча исчезли

Блок `.docs-content` — оформление импортированного HTML из CMS — содержал 23
декларации вида `color: hsl(var(--fg))` и `border: 1px solid hsl(var(--border))`.
Это наследие Tailwind v3, где токены хранились тройками `H S L` без обёртки. После
перехода на v4 токены — готовые цвета (`--fg: #111827`), и `hsl(#111827)` —
невалидный CSS: браузер отбрасывает декларацию целиком.

Блок используется реально, через `ContentRenderer`, то есть весь импортированный
контент рендерился без заданных цветов, без границ таблиц, без фона шапок таблиц,
без цвета ссылок и без заливки встроенных кнопок. Снаружи это малозаметно: цвет
текста наследуется от `body` и совпадает. Заметно становится там, где токен отличается
от унаследованного, — то есть на ссылках, рамках и кнопках.

Обёртка снята, `no-dead-token-function` не даёт ей вернуться. Правило ловит не
только `hsl(var(--…))`, но и `rgb`, `oklch`, `lab` и прочие: причина одна и та же.

### 10.10. Мёртвый блок MAX в `globals.css` ломал тёмную тему миниаппа

Первые 118 строк `app/globals.css` содержали стили расписания MAX из ранней
версии miniapp. `app/max/max.css` давно переопределяет те же классы, поэтому блок
был не нужен — но он не был удалён, а продолжал применяться.

`ScheduleView` вешает класс `max-schedule` на корень `<MaxUI>`. В `max.css` базового
правила для него нет, поэтому легаси-правило из `globals.css` применялось без
конкуренции и задавало `background: #f2f3f5` и `color: #111214` — **в обеих темах**.
Тёмная тема на главном экране бота не работала: тёмный токенный текст не появлялся,
потому что фон и цвет были заданы литералами выше по каскаду.

Там же `.max-schedule__type` получал из легаси `max-width: 92px` и `display: none`
на ширинах до 420px. MAX — это узкий экран, то есть подпись вида занятия, ради
которой в §3.5 и в §10.5 выведены пороги контраста 4.5:1, **не отображалась
практически ни на одном телефоне**. Размер 12px переопределялся `max.css`, а
`display: none` — нет.

Блок удалён целиком. В `max.css` в `.max-schedule__pair` добавлен
`color: var(--text-secondary)`: раньше этот приглушённый цвет приходился легаси-блоком,
и он был единственным местом в миниаппе с цветом вне токенов.

Заодно устранена невалидная конструкция: `@import "tw-animate-css"` стоял после
правил, то есть по спецификации CSS игнорировался. PostCSS его всё равно подхватывал,
поэтому анимации работали — правило просто не работало по заявленному механизму.

### 10.11. Палитра Tailwind мимо токенов: долг зафиксирован, а не спрятан

58 мест в расписании, корректировках и журнале задают цвета вида
`bg-emerald-100 text-emerald-700 dark:bg-emerald-950/60 dark:text-emerald-300`.
Это ровно то дублирование, которое §10.5 закрыло для цветов типов занятий, —
возвращённое с другой стороны: свой набор оттенков на каждое состояние, свои
значения в тёмной теме, ничего в режиме высокой контрастности.

Раньше это было не видно: `no-raw-hex` ловит только литералы `#hex`, а классы
палитры литералами не выглядят. Правило `no-raw-palette` добавлено, а найденный
долг записан в baseline одной строкой на нарушение. Baseline перестал быть пустым
не из-за регрессии, а потому что долг впервые измерен.
