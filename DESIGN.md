# Дизайн-система CollegeLMS

Единственный нормативный документ. Описывает систему **в том виде, в каком она
реализована сейчас**. Значения в документе и в `CollegeLMS.Next/app/globals.css`
должны совпадать; расхождение — дефект.

Исторические документы дизайна не задают правил и не являются источником истины.

---

## 1. Идентичность

Колледж — государственное бюджетное профессиональное образовательное учреждение.
Тон: сдержанный, академический, открытый. Никакой «стартапной» яркости.

Знак — герб с тёмно-синей окантовкой щита, лазурным глобусом, зелёными лавровыми
ветвями, сиреневой лентой с именем и кремовым отражателем. Палитра интерфейса
настроена на лазурно-синий и зелёный из знака; ленты и крема в интерфейсе нет.

## 2. Где живут токены

Все токены объявлены в **`CollegeLMS.Next/app/globals.css`**:

| Блок | Назначение |
| --- | --- |
| `:root` | светлая тема |
| `.dark` | тёмная тема |
| `@theme inline` | маппинг `--color-*` для Tailwind v4 + `--font-sans` + анимации |
| `.accessibility-mode` | режим высокой контрастности (не токены, а принудительные переопределения — см. §6) |
| `.prose`, `@layer components` | типографские и контентные помощники |

Отдельных файлов `tokens/` нет. Это осознанно: единственный источник истины —
один файл, который редактируется вместе с `@theme inline`, поэтому рассинхрон
между токеном и его Tailwind-утилитой невозможен по построению.

### 3.3. Правило токена `primary`

`--primary` — алиас `--accent`. Он используется и как заливка (`bg-primary`),
и как цвет текста (`text-primary`). В тёмной теме это **светлая лазурь**,
поэтому `text-primary` допустим только на тёмных поверхностях
(`bg-card`, `bg-muted`, `bg-background`), а не на светлых плашках
(`bg-accent-light`, `bg-secondary`). Нарушение этого правила — самый частый
источник нечитаемого текста; проверяется гейтом §8.

### 3.4. Утилиты MAX-приложения

MAX — отдельное мини-приложение в Telegram со своей палитрой в
`CollegeLMS.Next/app/max/max.css` (блоки `.max-app` и
`@media (prefers-color-scheme: dark)`). Токены: `--background-surface-*`,
`--stroke-*`, `--text-{primary,secondary,tertiary,themed,positive,negative,selfstudy}`,
`--accent-themed`.

**Известное отклонение:** тёмная палитра MAX переключается по системной теме
ОС, а не по переключателю темы приложения. Это осознанно не менялось.

## 4. Типографика

Единственный шрифт — **Inter** (`@fontsource/inter`, веса 400/500/600/700),
подключается через `--font-sans`.

Шкала задаётся утилитами Tailwind, отдельной типографской шкалы токенов нет:

| Роль | Утилита | Размер |
| --- | --- | --- |
| Заголовок страницы | `text-3xl font-bold` | 30px |
| Заголовок секции | `text-2xl font-semibold` | 24px |
| Подзаголовок | `text-xl font-semibold` | 20px |
| Основной текст | `text-base` | 16px |
| Вторичный текст | `text-sm` | 14px |
| Подпись, метка | `text-xs` | 12px |

В `body` жёстко задан `font-size: 16px` и `font-feature-settings:
"cv02","cv03","cv04","cv11"` (Inter Character Set — визуально ровные знаки).

## 5. Пространство, форма, глубина

- Отступы: шаг 4px (`p-1`…`p-12` в единицах Tailwind).
- Базовый радиус: `--radius: 0.5rem` (8px). У примитивов — `rounded-md`
  (контролы) и `rounded-lg` (карточки и панели).
- Границы: `border` + `--border`; базовый слой включает `* { @apply border-border }`,
  поэтому цвет рамки наследуется от токена, а не задаётся вручную.
- Тени: `shadow-sm` для карточек, `shadow-lg` для оверлеев и модальных окон.
- `html { scrollbar-gutter: stable }` — полоса прокрутки резервируется всегда,
  чтобы не было горизонтального сдвига при блокировке скролла.

## 6. Доступность

### 6.1. Базовые требования

- Интерактивные элементы — не меньше 44×44px (`min-h-11`, `size-11`).
- Видимый фокус: `focus-visible:ring-2 ring-ring` (или `outline`).
- Иконки — `lucide-react`, размеры `h-4` (в тексте), `h-5` (кнопки),
  `h-6` (заголовки). Иконка без подписи получает `aria-hidden`.
- Поля формы: видимая подпись, ошибка под полем, связь через `aria-describedby`,
  обязательность через `required` и `aria-required`.
- Состояние загрузки формы объявляется `role="status"` c `aria-live="polite"`.

### 6.2. Режим высокой контрастности

Переключатель `AccessibilityToggle` добавляет на `<html>` класс
`.accessibility-mode`. Это **не набор токенов**, а набор принудительных
переопределений:

| Правило | Эффект |
| --- | --- |
| `font-size: 18px; line-height: 1.6` | увеличенный текст |
| `img, video { display: none }` | скрытие декоративной графики |
| `* { animation: none !important; transition: none !important }` | отключение движения (кроме `.animate-spin`, `.animate-pulse`) |
| `a, button { text-decoration: underline; font-weight: 600 }` | подчёркивание ссылок и кнопок-как-ссылок |
| `.card, [class*="card"] { border-width: 2px }` | усиленные рамки |
| `body, .bg-white, [class*="bg-"] { background: #fff !important; color: #000 !important }` | чёрно-белая схема |
| `[class*="text-"] { color: #000 !important }` | весь текст чёрный |
| `button:has([class*="lucide"]) { background: rgba(0,0,0,.08) !important }` | рамка вокруг иконочных кнопок |

**Известные ограничения режима (зафиксированы, не исправлены):**

1. Класс применяется в `useEffect` компонента `AccessibilityToggle`, то есть
   только после гидратации и только на поверхностях, где есть переключатель.
   На MAX-поверхности переключателя нет.
2. Селекторы `[class*="bg-"]` и `[class*="text-"]` с `!important` сносят любые
   цветные поверхности, включая статусные плашки: в этом режиме информация о
   статусе передаётся только текстом.
3. `img, video { display: none }` скрывает в том числе логотип.

## 8. Проверки

Две проверки запускаются командой `npm run check:design-system`.

### 8.1. `scripts/check-design-system.mjs` — правила исходников

| Правило | Что запрещает |
| --- | --- |
| `no-raw-hex` | литералы цвета в `.ts`/`.tsx` — только токены |
| `no-transition-all` | `transition-all` вместо перечисления свойств |
| `no-raw-select` | нативный `<select>` вместо примитива `Select` |
| `no-raw-table` | нативный `<table>` вместо примитива `Table` |
| `required-file` | наличие обязательных файлов |
| `forbidden-file` | отсутствие устаревших файлов |

Сейчас в baseline 36 известных нарушений (11 `no-raw-hex`, 12 `no-raw-table`,
12 `no-transition-all`, 1 `forbidden-file`). Проверка падает **только на новых**
нарушениях — старые видны и постепенно разбираются.

### 8.2. `scripts/check-token-contrast.mjs` — контраст

Считает WCAG 2.1 по 15 парам в светлой теме, 15 в тёмной, 3 в режиме высокой
контрастности и по 2 в каждой теме MAX. Пороги: 4.5:1 для текста, 3:1 для
границ и колец фокуса.

Текущий baseline — 4 известных нарушения:

| Тема | Пара | Контраст | Комментарий |
| --- | --- | --- | --- |
| тёмная | `primary-foreground / primary` | 3.33:1 | белый на светлой лазурной заливке |
| тёмная | `accent-foreground / accent` | 3.33:1 | тот же токен под другим именем |
| тёмная | `input / background` | 1.72:1 | граница поля темнее фона, но светлее порога |
| светлая | `input / background` | 1.58:1 | граница поля слишком светлая |

Проверка падает **только на новых** нарушениях. Обновить baseline осознанно:
`node scripts/check-token-contrast.mjs --update`.

### 8.3. Тесты

`npm run test:e2e` — Playwright, два проекта: `chromium` и `mobile` (Pixel 5).
Покрыты: контраст тем, отсутствие горизонтального переполнения на 320px,
доступность форм, размеры интерактивных элементов.

## 10. Известные особенности и дефекты

Внешний вид считается согласованным. Ниже — только то, что важно знать при
работе с системой; правки требуют отдельного согласования, потому что меняют
поведение или облик.

### 10.1. Дефект

1. Логотип на странице авторизации схлопывался до ~16px: `w-full` на `<img>`
   разрешался относительно контейнера, сжатого `align-items: center`. Исправлено
   фиксированной шириной (`w-64`) и `w-full` на контейнере.

### 10.2. Осознанные решения, выглядящие как дефекты

2. Верхний ряд публичной шапки скрывается при скролле (`-translate-y-full h-0`),
   из-за чего высота шапки меняется. Это задумано: комментарий в коде
   «hides on scroll via transform (no layout shift)». Анимируется только
   `transform`, высота меняется мгновенно.
3. Drawer-меню не анимируются: классы `animate-in`, `fade-in-0`,
   `slide-in-from-*` пришли из пакета `tailwindcss-animate`, которого в проекте
   нет (установлен `tw-animate-css`). Панель появляется мгновенно.
4. Тёмная палитра MAX переключается по системной теме ОС, а не по
   переключателю темы приложения.
5. Граница поля ввода не достигает порога 3:1 ни в светлой, ни в тёмной теме —
   см. baseline §8.2. Поля читаются за счёт подписи и заливки, не за счёт рамки.

### 10.3. Ограничения режима высокой контрастности

6. Класс применяется в `useEffect` компонента `AccessibilityToggle`, то есть
   только после гидратации и только на поверхностях, где есть переключатель.
7. Селекторы `[class*="bg-"]` и `[class*="text-"]` с `!important` сносят любые
   цветные поверхности, включая статусные плашки: в этом режиме информация о
   статусе передаётся только текстом.
8. `img, video { display: none }` скрывает в том числе логотип.
9. `text-primary` в тёмной теме нечитаем на светлых плашках — см. §3.3.
