# Учебные материалы по разработке

Скилл для репозиториев `mdk0102`, `mdk0901`, `mdk0103_*`, `mdk0104_*`,
`UP09`, `StudyPractice-*` и любых методичек колледжа.

## Принцип

Материал — не конспект ради конспекта, а сценарий занятия: студент должен
суметь повторить результат руками. Один материал = одна проверяемая цель.

## Обязательная структура

1. **Тема и цель** — что студент сможет сделать после занятия.
2. **Планируемые результаты** — знания/умения/компетенции (ПК/ОК), связь с
   рабочей программой.
3. **Теория** — минимум, необходимый для практики; термины раскрыты при первом
   употреблении; без «воды» и истории ради истории.
4. **Разобранный пример** — код/команды целиком, с ожидаемым выводом.
5. **Практикум** — пошагово, с проверяемыми промежуточными результатами.
6. **Самопроверка** — вопросы/тесты с ответами или критериями.
7. **Домашнее задание** — вариант/усложнение, не копия практикума.
8. **Критерии оценивания** — таблица «критерий → баллы → что должно быть».
9. **Источники** — официальная документация, версии, дата актуальности.

Для нескольких занятий добавляй оглавление и навигацию «предыдущее/следующее».

## Качество кода и команд

- Указывай версии: .NET, Node.js, PostgreSQL, пакетов.
- Команды копируются и выполняются без правок; пути — относительные.
- Код полный: нет «…» и «допишите сами» в разобранном примере.
- Ожидаемый вывод/скриншот — рядом с командой.
- Пароли, токены, строки подключения — только заглушки, не реальные секреты.
- Ошибки — часть материала: типичная ошибка, причина, исправление.

## Оформление

- Markdown: заголовки `##`/`###` без пропуска уровней, код-блоки с языком,
  таблицы для сравнений, Mermaid для схем.
- Длина строки — до 100 символов; один абзац — 3–5 строк.
- Скриншоты: актуальный UI, обрезаны до нужной области, с подписью; не
  заменяй текст скриншотом.
- DOCX/PDF — через скиллы `office-docx`, `office-export-pdf`; проверяй
  разрывы страниц и таблицы через `office-render`.
- Имена файлов: `NN-тема.md` или `NN-тема.docx`; без пробелов и кириллицы в
  путях, если репозиторий уже следует такому правилу.

## Чек-лист перед сдачей

- [ ] Цель измерима и совпадает с практикой.
- [ ] Все команды выполнены в чистом окружении.
- [ ] Пример кода запускается, вывод совпадает.
- [ ] Нет секретов и реальных персональных данных.
- [ ] Термины объяснены; нет ссылок на «см. выше» без якоря.
- [ ] Критерии оценивания позволяют поставить балл без субъективности.
- [ ] Ссылки живые, версии актуальны, дата указана.
- [ ] Оглавление/навигация обновлены, README репозитория ссылается на файл.
- [ ] DOCX/PDF (если есть) отрендерены и проверены визуально.

## Типичные ошибки

- Простыня теории без практики и без проверки понимания.
- Пример «в вакууме», не связанный с практикумом.
- Устаревшие скриншоты и версии пакетов.
- Тест без ответов или с ответом «см. лекцию».
- Критерии «сделал/не сделал» без градаций.
- Копирование материала между специальностями без адаптации примеров.

## Конвейер coursekit (МДК 01.04 ИБ)

В `mdk0104_IB`, ветка `feature/course-pipeline`, есть готовый конвейер:
Markdown в `course/` — единственный источник, из него собираются DOCX (pandoc),
PDF (Typst), PPTX, схемы Mermaid, сборник и QA-отчёт.

```bash
python -m coursekit qa                 # отчёт dist/qa-report.md
python -m coursekit qa --strict        # 1 и на WARN
python -m coursekit build --section 1  # docx/pdf/pptx/figures/qa
python -m coursekit build --book       # весь курс + сборник
python -m coursekit normalize --check   # 1, если нормализация изменит файлы
```

Уровни QA:

- **ERROR** (сборка падает): не один H1, незакрытый блок кода, битая
  локальная ссылка;
- **WARN**: нет обязательного раздела (лекция — план/резюме/вопросы,
  практика — цель/ход/варианты/критерии), нет языка у блока кода, прямые
  кавычки в русском тексте, устаревший стек, `TODO`, слишком короткий/длинный
  текст.

Правила: имя файла задаёт вид и номер (`Лекция N. Тема.md`,
`Практическая работа N. Тема.md`, `Самостоятельная работа N. Тема.md`);
заголовок H1 один; разделы `##` с допустимыми синонимами. Перед правкой
материала прочитай `docs/pipeline.md` и `dist/qa-report.md`.

Если ветки с coursekit нет — не изобретай свой генератор, сначала предложи
перенести конвейер в репозиторий.

## Работа с репозиторием

1. Прочитай `AGENTS.md` и README репозитория, посмотри соседние занятия —
   сохраняй сложившийся формат.
2. Не переименовывай и не удаляй файлы без явной просьбы.
3. Обновляй индекс/README, если добавил занятие.
4. Коммит — в рабочую ветку; сообщение `docs: <тема>`.
5. Для массовой проверки используй `subagent` по одному занятию на ребёнка и
   сводный отчёт родителя.
